摘要翻译（忠实原文）

前沿模型评估正在从基础能力（instruction following、reasoning）转向组合式、agentic 能力，但韩语 agentic benchmark 仍然稀缺。本文提出 K-BrowseComp——一个基于韩国语境的 web browsing agent benchmark，包含 400 个问题。其中 300 题的 K-BrowseComp-Verified 子集 由韩语母语者手工构建并验证。在该子集上，前沿 LLM（包括 GPT-5.5 / DeepSeek-V4-Pro / GLM-5.1）仅达到 30.00%–45.67% 准确率——这相对 BrowseComp 有显著下降；而通过韩国 Proprietary AI Foundation Model (PAIF) program 发布的韩国主权 LLM 仅取得 0.00%–10.33%。作者进一步构建 100 题的 synthetic split：使用难例 few-shot 样本 与 failure-mode-targeted generation，利用"解决问题 vs 创造问题" 的不对称性生成对抗式过滤后的合成诊断分片；在该 adversarial split 上，最强模型仅达到 26.00%——作为独立的 targeted stress test 单独报告。数据与代码已公开发布。

核心内容解读（约 560 字）

问题背景：2026 H2 agent benchmark 的评估重心已从"instruction following / reasoning" 转向 组合式、agentic 能力——最典型的 BrowseComp（Anthropic + OpenAI 主导）通过 web browsing 任务测试 agent 的 reasoning + tool use + web navigation 三合一能力。但 BrowseComp 是英语语境，问题、URL、页面内容全是英语——它测的是"英语 web + 英语推理" 而非"web agent 通用能力"。韩语 agentic benchmark 稀缺 意味着韩国主权 LLM（政府 PAIF program 资助）无法被公平评估，同时前沿 LLM 在非英语 web 上的真实表现被系统性掩盖。

核心方法：K-BrowseComp 三大方法学突破。(1) 韩语母语者手工构建 300 题——不是把英语题机器翻译，而是从韩国语境本身提问（如涉及韩国政府部门、韩国大学历史、韩国专利数据库、韩国法律条文）；(2) 韩语母语者独立验证——每题至少 2 名母语者交叉验证 golden answer 存在且可获取；(3) 100 题 adversarial 合成 diagnostic split——利用"solving vs creating 不对称" 方法学：给 LLM 硬难 few-shot 例子 + 失败模式定向生成 prompt，让 LLM创造出它自己解不了的题——这本质上是探索 LLM 能力边界的自动化方法。

关键实验数据：(1) 前沿 LLM 30-46%（GPT-5.5、DeepSeek-V4-Pro、GLM-5.1）——远低于同一模型在 BrowseComp 英语上的表现，证明语言不是薄涂层而是结构性能力障碍；(2) 韩国 PAIF 主权模型 0-10.33%——数字令人震惊，揭示韩国主权 AI 生态在 agentic 能力上的严重滞后——这对 PAIF program 政策制定者是直接警示；(3) adversarial diagnostic split 最强模型 26%——说明 K-BrowseComp-Verified 距离饱和还很远，adversarial 空间还有巨大探索余地。方法学突破：solving vs creating 不对称 是本文最重要的元贡献——LLM 更容易创造出它自己解不了的题，这个不对称性可作为所有 benchmark saturation 抵抗的通用手段（不只韩语、不只 web browsing）。H2 benchmark 谱系再拓展一格：第十二联 · 语言主权联 (Language Sovereignty League)——十一联（物品/搜索/评委/构造/配置/价值观/多语言/文化/严重度/统一红队/立法接地/本联）。政治意义：韩国主权 LLM 0-10.33% 直接质问 PAIF program 战略——政府资助的国家级基座是否真的具备 agentic 能力？

三大观察：(1) 语言瓶颈是结构性的——同一模型跨语言表现落差 20+ pp；(2) 主权 LLM 差距是量级性的——0.00-10.33% vs 30-46% 意味着现在的韩国主权 LLM 几乎无法完成韩国语境 web browsing 任务；(3) Adversarial split 26% 说明该 benchmark 远未饱和，是 H2 韩语 agent 能力真正的挑战面。

Solving vs Creating 不对称 —— 100 题 Adversarial Split 的方法学基础

核心洞察：LLM 有一种奇特的不对称性——它更容易生成一道它自己解不了的题，而不是解一道类似难度的题。这是因为 创造问题只需要局部知识组合的合法性，而解决问题需要完整的推理链。K-BrowseComp 系统性利用这个不对称性生成 diagnostic split：

  • 步骤 1：从 K-BrowseComp-Verified 中提取失败模式——每种失败对应一类推理陷阱（多跳歧义 / 韩国专有名词消歧 / 时间锚定 / URL 结构假设等）
  • 步骤 2：用 难例 few-shot exemplars prompt LLM，让它模仿这些失败模式生成新问题——但答案由问题的知识组合决定，不由 LLM 提供
  • 步骤 3：Failure-mode-targeted generation——针对每个 failure mode 单独生成 targeted 子集，确保 diagnostic split 有清晰的 failure taxonomy
  • 步骤 4：Adversarial 过滤——只保留同一 LLM 无法自解的题——这就是"把 LLM 自己作为 hard example filter" 的自动化 curator

这套方法学可以推广到任何 benchmark 的 saturation 抵抗——不需要每次找人工出题，只要有 seed failure modes + LLM 就可以自动生成 adversarial split。这与 5-27 TASTE (2605.28556) 的 "reversed benchmark construction" 是同一思想的不同 instantiation。

对研究方向的启发
对 Harness Engineering

Web browsing agent harness 的语言差异性——K-BrowseComp 揭示 harness engineering 在英语外的语言语境需要重新设计：(1) URL 结构假设（英语 URL 是 latin，韩语 web 有大量非 latin URL）；(2) HTML 结构（韩语 web 有独特的 layout convention · e.g. 韩语常见的 side-nav 布局）；(3) 搜索关键词生成（英语 harness 假设 keyword 是空格分隔，韩语是 subword 粘连）；(4) 时间锚定（韩国日期格式、公历/檀君纪年混用）。与今日 harness 报告 (Better Harnesses, Smaller Models) 呼应：作者的 meta-agent 完全可以针对 K-BrowseComp 自动发现"韩语 web browsing harness 适配"——为韩国主权 LLM 自动生成 adapted harness，可能让它们从 10.33% 跃升到 30-40%。

对 Agent Safety

K-BrowseComp 反过来指向"韩国主权 LLM 的 safety 也可能被系统性低估或高估"——如果一个模型在能力层面只有 10%，那么它 refuse 率高看起来"safe"，但可能只是不知道该怎么 unsafe 而已。启发：(1) safety benchmark 必须与 capability benchmark 同时报告——safety score / capability score 双元组是判断"真安全 vs 假安全" 的最小观察单元；(2) 与今日 agent safety 报告 (Singapore AISI × Korea AISI Data Leakage) 呼应——AISI 报告发现"三 agent 无一 correct + safe 双正"，K-BrowseComp 提供了"K-BrowseComp × KSAFE-MM 双 benchmark 覆盖韩语能力 + 韩语安全" 的完整方案；(3) 韩国主权 LLM 差距警示——政府主导的国家级基座模型如果在 agentic 层面滞后，safety alignment 也必然滞后，AISI 类机构应把"能力 gap"纳入 safety risk taxonomy。

对 Benchmark

H2 benchmark 谱系再拓展一格 · 第十二联：语言主权联 (Language Sovereignty League)——十一联（物品/搜索/评委/构造/配置/价值观/多语言/文化/严重度/统一红队/立法接地/本联）。核心方法学贡献：(1) solving vs creating 不对称 应成为所有 benchmark 抵抗 saturation 的默认协议——不用手工 curator 就能持续生成 adversarial split；(2) 母语者手工构建 + 母语者交叉验证 是 "非英语 benchmark" 的最小可信度基线；(3) 主权 LLM 独立报告——benchmark 应显式区分"前沿闭源 vs 国家主权 vs 开源社区" 三大生态，因为它们的目标函数和资源约束完全不同；(4) diagnostic split 独立报告——不合并到主分数，作为 targeted stress test 独立展示——这是本文首创的方法学。H2 benchmark 未来预测：K-BrowseComp × J-BrowseComp × ZH-BrowseComp × Ar-BrowseComp 家族化——每个主权国家的 web agent benchmark 化，最终形成 "BrowseComp Family" 全球评估网络。
