一句话核心贡献
把 agent benchmark 的构造过程反转：先合成合法工具序列（ACE n-gram），再聚类选代表，再实例化为任务，最后迭代难度演化——由此得到的 τc-Bench 让 near-saturated 模型骤降 44-53 pp、工具组合覆盖翻倍，实证"现有 benchmark 的高分反映的往往是饱和而非真实鲁棒能力"。
摘要（中文翻译，忠实原文）

随着 agent 能力的进步，现有 benchmark（如 τ²-Bench）正在快速饱和。然而构造新的 benchmark 任务仍然复杂、昂贵、劳动密集；更棘手的是——标准做法（先用自然语言写场景，再映射为工具序列）只能捕捉 agent 真实使用的狭窄子集。本文通过反转任务构造过程 来解决这些问题。

我们提出 TASTE：Task Synthesis from Tool Sequence Evolution——一种自动方法，生成更难 且覆盖度更广 的任务。TASTE 使用一个 Adaptive Contrastive n-gram 模型——在 LLM-judged validity 信号上训练，从而能采样合法的工具序列，覆盖广大的工具组合空间。TASTE 随后通过聚类 从池中选取代表性序列，把它们实例化为完整的 benchmark 任务，并通过迭代难度演化 精修任务。

用 TASTE，我们构造 τc-Bench——τ²-Bench 三领域的挑战性扩展。评测 11 组 agent/user LLM pairs，发现那些几乎饱和 τ²-Bench 的模型 在我们的任务上性能严重下降——例如 Gemini-3-Flash 从 0.82-0.94 降到 0.28-0.61。除了提高难度，我们生成的任务把 agent 必须执行的独特工具组合数量翻倍以上。我们的结果表明：在现有 benchmark 上取得的高分，往往反映的是饱和 而不是robust 任务求解能力。TASTE 通过自动化难题、高覆盖 benchmark 的生成，实现了对未来 agents 的连续、可扩展评测。

核心内容解读（问题 / 反转构造 / ACE n-gram / 聚类抽样 / 难度演化 / τc-Bench 实证 / 四联拍立场）

问题背景。agent benchmark 领域正面临三重危机：(1) 饱和危机——τ²-Bench / GAIA / WebArena / SWE-bench 上顶尖模型已到 0.85-0.95；(2) 构造危机——手工写 benchmark task 复杂昂贵；(3) 覆盖偏差危机——传统"自然语言场景 → 工具序列" 流程只覆盖 agent 真实工具使用的一小部分，因为人类作者不会 想到所有工具组合（多 tool 联合、异常 tool 顺序、稀有 tool 参数化）。本文的洞见：反转它——如果先合成合法工具序列，再把它翻译成任务描述，就能覆盖到人类想不到的组合。

反转构造 pipeline。TASTE 的完整流程是四步走：

步骤动作技术
1训练一个能采样合法工具序列的模型Adaptive Contrastive n-gram (ACE)——在 LLM-judged validity 信号上训练
2从 ACE 采样海量合法工具序列覆盖大范围工具组合空间
3从池中选代表性 工具序列聚类抽样（vector similarity clustering）
4把序列实例化 为完整任务 + 迭代难度演化LLM synthesizer + iterative difficulty evolution

Adaptive Contrastive n-gram（ACE）——方法学核心。ACE 是一个n-gram 语言模型，但训练目标不是"下一个 token"，而是"下一个 tool"。它对比 学习：给定当前工具序列前缀，哪些下一个工具是合法后继（能被 LLM judge 认可为合法组合）、哪些不合法。"Adaptive" 指模型可根据 validity 信号自适应调整—— 不需要大量标注数据，只需要一个能给 validity 判断的 LLM judge。ACE 的优点是可采样——不像 GAN / VAE 生成质量不可控，n-gram 天然支持温度采样、限制长度、条件采样。

聚类选代表——覆盖 vs 精选的关键。ACE 可以采样海量合法序列，但直接把它们全部实例化为任务会造成两个问题：(a) 冗余——很多序列在语义上等价；(b) 不平衡——常见组合被过度采样，稀有组合被淹没。TASTE 用聚类（对工具序列做 embedding + k-means）从池中选代表性 序列——保证覆盖广 且去冗余。这一步是 τc-Bench 独特工具组合数翻倍 的关键。

迭代难度演化。选出代表序列后，用 LLM synthesizer 把它们实例化为完整的自然语言任务（含 user goal / 上下文 / 约束）。然后进入难度演化循环：让当前 SOTA agent 试解，成功的任务在下一轮被加难度（增加约束、引入干扰工具、改成 multi-hop、隐藏关键信息等），失败的任务保留。经过若干轮演化，最终得到near-adversarial 但仍solvable 的任务集。这条与 6-08 Hacker-Fixer Loop（对抗性 verifier hardening）在思路上相通——都用对抗式循环 提升 benchmark 质量，但作用位置不同：Hacker-Fixer 硬化 verifier，TASTE 硬化 task 本身。

τc-Bench 实证数据震撼。作者在 τ²-Bench 的三个领域（travel / retail / airline）上应用 TASTE，得到 τc-Bench。评测 11 组 agent/user LLM pairs——包括 Gemini-3-Flash、Claude 系列、GPT 系列、开源模型。核心结果：

  • Gemini-3-Flash：τ²-Bench 上 0.82-0.94 → τc-Bench 上 0.28-0.61（下降 44-53 pp）
  • 其它 near-saturation 模型：普遍出现严重下降——说明饱和不是真实鲁棒
  • 独特工具组合数：×2 以上——覆盖度实质突破

这三条数据合起来给出强命题：near-saturated 模型的高分是构造 bias 的产物，不是 robust 能力的证据。

Harness Engineering

(1) 把"任务合成"提升为 harness 一等公民——现在的 harness 主要负责运行任务，未来 harness 应内置"任务合成子系统"（TASTE 风格），让 harness 具备自我扩充测试集 能力，避免 benchmark 老化拖垮 harness 有效性；(2) ACE n-gram 是极好的轻量、可采样、可控 生成模型——你的毕设 KR1 (ProofFlow Kernel Agent) 也可以借鉴：把 GPU kernel design 的合法内核 IR 序列 用 ACE n-gram 学习，Agent 输出从"直接生成 kernel" 变为"ACE 采样合法 IR 前缀 → LLM 补足细节"——搜索空间显著受限而可靠性提升；(3) 迭代难度演化 pipeline 可以复用为 harness 的"自演化 stress test"——harness 每周自动生成一批更难任务，检验最新模型的边界；(4) 与 7-02 Loop Engineering 联动：TASTE 生成的任务可以自然对应"loop specification"（每个 τc-Bench 任务 = 一份 loop spec），loop library 从手工编码 升级为自动合成；(5) 你可以做 KV-cache-aware TASTE：让 ACE 采样偏向生成"能显著测试 KV-cache reuse 边界" 的工具序列——比如刻意生成含共享长 prefix 但 branch out 的多轮任务，构造你毕设方法的"压力测试集"；(6) TASTE 对 benchmark 老化 的诊断 —— 与 5-13 The Evaluation Differential / 6-22 Evaluation Awareness 组合，harness 的寿命管理 成为独立研究子方向。

Agent Skills Safety

(1) TASTE 直接可用于生成 skill safety benchmark——让 ACE n-gram 采样"合法但危险" 的工具序列（例如 read_file → base64 → send_email = exfiltration 模式），比人手写 red-team 场景覆盖更广；(2) 与 6-12 DECOMPBENCH（Decomposition Attacks）天然联动——decomposition 攻击的成功依赖于"把有害任务拆解为子任务序列"，这正是 TASTE 反向能采样的对象：TASTE-adversarial 采样 decomposition-style 序列，DECOMPBENCH 从"手工场景"升级为"自动合成"；(3) 与 7-03 BOA（搜索派）联动：BOA 讲搜索轨迹空间，TASTE 讲合成任务空间——两者结合形成"合成任务 → 搜索轨迹 → 评估安全" 完整 pipeline；(4) 迭代难度演化 可以做为agent safety 的"攻击强度演化"——每一轮找到 agent 防御不了的近边界 攻击，下一轮加难；(5) 反饱和 是 skill safety benchmark 的紧迫需求——SkillSafetyBench / SafetyBench 上现代模型已到 0.9+，需要 TASTE 风格再生成；(6) 立即可用：ACE 训练需要 LLM validity judge——把它换成 safety judge（判"该工具序列是否安全"），就能得到 Safety-ACE，专门采样边缘 unsafe 序列。
