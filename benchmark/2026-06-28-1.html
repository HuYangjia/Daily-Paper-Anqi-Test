摘要（中文翻译，忠实原文）

视觉-语言模型（VLM）越来越被用作嵌入式智能 在安全关键物理系统中的感知-推理 backbone——感知或推理错误会直接导致不安全的决策或动作。虽然许多红队方法 已经被开发出来用以检测 VLM 漏洞，但这些方法的评估在数据集、指标和威胁模型上是碎片化的，使得直接比较变得困难，并掩盖了观察到的差异究竟来自更强的攻击、更脆弱的模型，还是不兼容的评估设置。已有的以聊天机器人为中心的红队基准主要标准化了越狱 和内容安全 的评估，但它们没有系统性地捕捉物理层面的功能性失败，也没有覆盖针对物理世界 VLM 的红队方法。这就提出了一个关键挑战：如何在统一协议下比较多样攻击方法，并同时针对相同的、场景特定的失败。

我们提出 REALM，据我们所知第一个 面向物理世界 VLM 的统一红队基准。REALM 整合了12 种红队方法、3 种模型无关防御、13 种 VLM，在实用的黑盒威胁模型 下使用共享数据集和指标。为了在不同攻击家族间对齐对抗目标，REALM 引入agentic target-generation pipeline，为每个场景构造共享的、场景特定的、物理依据的攻击目标，从而让多样红队方法在对齐的对抗目标 下公平比较。我们的评估显示：文本与排版注入攻击诱发最多失败，多模态协同优化产生最强视觉扰动迁移，单次摊销攻击以远低的成本逼近迭代方法，并且模型规模本身并不带来对抗鲁棒性。代码已开源。

核心内容解读（agentic target-generation / 12 攻击家族 / 单次摊销 / 防御无法泛化）

动机：物理世界 VLM 红队评测碎片化到无法直接比较。过去两年红队方法迅速膨胀——FOA-Attack（最优传输对齐）/ M-Attack（余弦相似）/ V-Attack（注意力 Value）/ CoA（多模态协同优化）/ PhysPatch（物理补丁）/ AdvDiffVLM（扩散潜空间）/ AdvEDM（注意力语义编辑）/ AnyAttack（单次前向）/ FigStep（排版注入）/ PromptInject（文本注入）—— 但它们的数据集、指标、目标定义 各不相同。当你看到"方法 A 在驾驶 ASR 70%" 而"方法 B 在抓取 ASR 50%" 时，无法判断 是 A 更强、B 更弱，还是评测设置本身不兼容。HarmBench / AgentHarm / OpenRT 等 chatbot 红队 benchmark 标准化了越狱，但物理世界 VLM 的 functional failure（误判车辆方向 / 抓取力过大 / 物理推理颠倒）从未被统一。

关键设计 ① agentic target-generation pipeline。REALM 最有价值的方法学创新——把"攻击目标构造" 与"攻击实现" 解耦。流程：

阶段组件产出
1. 失败模式推理Reasoning VLM agent g（分析场景）识别 plausible failure mode（如驾驶误判机动方向 / 操控混淆夹爪方向）
2. 目标答案生成Agent g合理错误答案 $a^{\text{tar}}$（与场景一致但不同于真值）
3. 视觉目标合成Qwen-Image（文生图 / 编辑）目标图像 $I^{\text{tar}}$（视觉化错误感知）
4. 精化循环Agent g 诊断 + 重生成不匹配时迭代直到对齐
5. 答案抽取Qwen3-8B judge140,556 次调用，错误率仅 0.12%，无解析失败

校准证据：预攻击目标选择率仅 25.5%（接近 4 选 1 随机基线 25%），说明目标答案在攻击前未被系统性偏向——这是"目标无 bias" 的可量化证据。这个 pipeline 把"统一目标" 从"口号" 变成"可验证的工程构造"—— 直接补齐过去三年红队 benchmark 系统性缺失。

关键设计 ② 12 攻击家族 × 3 防御 × 13 VLM 完整矩阵。攻击按范式分组：(1) 代理集成梯度（FOA / MA / VA / PA）；(2) 多模态与补丁（CoA / PhysPatch）；(3) 生成与语义编辑（AdvDiffVLM / AdvEDM / AnyAttack）；(4) 注入与基线（FigStep / PromptInject / ImageMix）。防御均为模型无关预处理：PAD（补丁热图融合 + SAM 分割移除）/ FreqPure（高频保留扩散净化）/ BlueSuffix（图像去噪 + 文本净化 + 防御后缀）。VLM 覆盖 4 闭源（Gemini-3-Flash / Seed-2.0-Mini / GPT-4.1-Mini / Qwen3.6-Flash）+ 9 开源（Kimi-K2.5 / Qwen3.5 9B/27B/122B / Qwen3-VL 8B/30B/32B / Cosmos-Reason 1/2）。

核心论点：文本/排版注入 ≫ 视觉对抗—— 在物理世界 VLM 上，把恶意字符串"写在图里" 或"塞进 prompt" 比精心设计的像素扰动更便宜更有效。ImageMix（非对抗）44.8% ASR 是令人警觉的基线—— 这意味着 VLM 对任何 视觉污染都不稳健。

关键数据 ② 规模带不来鲁棒性。Qwen3.5 9B → 122B：清洁准确率 68.9% → 72.8%（+3.9 pp），但 PromptInject ASR 几乎不动（63.7% → 64.3%）。这把"scale solves alignment" 的乐观假设在物理世界 VLM 上反证—— 6 个月内陆续累积的"放大模型不能解决安全" 证据链在这里再添一笔（与 5-7 "Why Does Agentic Safety Fail to Generalize" 形成姊妹证据）。

关键数据 ③ 单次摊销逼近迭代。AnyAttack：1 秒/图、单次前向、49.9% ASR；FOA：300 步迭代、几百倍 GPU 成本、48.1% ASR。攻击成本 → 0，防御成本却随防御层堆叠线性上升 → 这是 H1 末 VLM 安全研究最被低估的成本不对称。

关键数据 ④ 防御没有跨范式泛化。BlueSuffix 把 PromptInject ASR 砍 21.7 pp（65.6 → 43.9）但对 FOA 仅降 4.6 pp；FreqPure 对 FOA 降 5.8 pp 但对 PromptInject 无效；PAD 对所有攻击几乎无效（≤ 0.3 pp）；任何防御对 FigStep 都是 0 效果。结论：单一预处理防御无法跨攻击范式泛化，必须多层组合—— 这与 6-26 AgentDoG 1.5 在 LLM 侧的"分类法 + 影响函数净化 + FSM-RL + 在线护栏 四层组合" 结构同构。

方法学位置：把"诊断性 benchmark" 思想推到红队评测层。把 H1 末 benchmark 链条排开：6-23 Eval-Awareness Multivariate（多变量评测）/ 6-25 Hacker-Fixer Loop（对抗加固 benchmark）/ 6-26 ForesightSafety-VLA（诊断性 VLA benchmark）/ 今日 REALM（红队统一协议）—— 形成完整的"评测维度多元化 × benchmark 对抗加固 × 诊断性分解 × 红队协议统一" 四拍闭环。REALM 与 ForesightSafety-VLA 的关系尤其有趣——前者是VLM 红队，后者是VLA 诊断，共构具身智能安全评测的"感知-行动双侧统一"。

对你三个研究方向的启发
Harness Engineering

REALM 对 harness 工程的启发是"把 harness 评测也做成 unified-protocol benchmark"：(1) agentic target-generation pipeline 可平移到 harness 评测—— 用 agent 自动构造"这个 harness 应该处理的目标任务"，让不同 harness 在共享目标 下被比较，避开过去 harness benchmark "各自定义任务" 的硬伤；(2) 12 攻击 × 3 防御 × 13 模型 矩阵思路—— 平移到 KV-cache 即 12 workload × 3 cache strategy × 13 model 的完整 sweep 矩阵；(3) 规模带不来鲁棒性 直接对偶KV-cache 命中率不会随模型增大自动提升—— 大模型反而对 cache miss 更敏感，应该是 KV-cache 研究的硬数字；(4) 单次摊销攻击 对偶单次摊销优化—— KV-cache 的 prefetch / hint 也可以是 single-pass 推理时决策，避免迭代搜索；(5) 非对抗基线（ImageMix） 思路—— KV-cache 评测应该有"random eviction" baseline，避免 LRU/LFU 的优势被夸大；(6) 与 6-28 Code Isn't Memory 形成双视角—— 一个是 harness 组件因果消融，一个是 harness 评测协议统一，两者构成完整的"harness 实验方法学" 工具箱。

Agent Skills Safety

REALM 的"统一红队协议" 思想对 agent safety 的直接启发：(1) agentic target-generation 应用到 skill safety——用 reasoning agent 自动构造"这个 skill 应该被攻击的合理失败目标"，避免人工标注 bias；(2) 12 攻击对齐到共享目标—— SkillSafetyBench 的 30 类别可以学这个范式，把异质攻击拉到同一目标做 head-to-head；(3) 规模不解决问题—— Qwen3 9B → 122B ASR 不变，意味着 RUBAS 这种训练信号 rubric 化 的方法比"等更大模型" 更可能解决问题；(4) 防御无法跨范式泛化—— BlueSuffix 在 PromptInject vs FigStep 上差异巨大，意味着 agent safety 的 guardrail 也必须多层组合（与 6-26 AgentDoG 1.5 的四层架构同构）；(5) 判别 judge 错误率 0.12%—— Skill safety 也应该用 Qwen3-8B 等小模型做 judge 但要控制错误率；(6) scaffold-attack pairing—— REALM 显示不同模型对不同攻击敏感度差异巨大（Cosmos-Reason2 PromptInject ASR 76.8%），暗示 skill safety 也存在"scaffold × model pairing 决定脆弱性"。

Safety Benchmark（直击方向）

这篇是 H1 末"统一协议红队评测" 的代表作，给你设计 safety benchmark 的方法学清单：(1) 统一目标—— 用 agentic pipeline 构造场景特定共享目标，让异质攻击/方法可比；(2) 预攻击校准—— 报告"目标答案选择率" 接近随机基线（25.5% ≈ 25%），证明 benchmark 本身无 bias；(3) 三轴矩阵—— 12 攻击 × 3 防御 × 13 模型 是 SAFETY 评测的下限规模，单一维度 ablation 已不够；(4) 非对抗基线—— ImageMix 44.8% ASR 是必备对照，让"对抗扰动" 的额外贡献可量化；(5) 跨规模实验—— 至少跑 3 个 size（9B / 27B / 122B），让"scale ≠ robustness" 这种结论可证；(6) 判别 judge 错误率—— 0.12% 是个值得追的目标；(7) 评测点数量级—— 129,792 评测点是 H2 safety benchmark 的新天花板；(8) 与 6-26 ForesightSafety-VLA 的L × W × V 三轴结合 = 感知层（REALM 红队）+ 行动层（VLA 诊断）+ 训练层（RUBAS rubric） 完整具身智能安全评测栈；(9) 防御无法泛化 数据应该写进每个 safety benchmark 的 limitation——单一 defense 不能 claim "universal safety"。
