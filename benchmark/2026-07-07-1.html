摘要（中文翻译，忠实原文）

Personal agents 正在成为持续存在的、用户拥有的中介：它们记住 preferences · 过滤平台中介的信息 · 使用工具 · 与服务谈判。既有 benchmark 评估 tool use / web navigation / desktop control / personalization / recommendation / evolving context，但很少 追问 agent 是否保留用户主权——在尊重隐私、consent、证据、用户负担、抵抗操纵激励的前提下 推进用户当前利益。我们提出 SovereignPA-Bench——一个可执行的 benchmark，用于评估 personal agent 在演化意图 · 平台中介 · 隐私边界 · consent 约束 · 证据要求 · 负担权衡 下的表现。Benchmark 把 agent-visible ObservableState 与 evaluator-only HiddenLabels 分离，报告 task success · alignment · privacy · consent · evidence · manipulation · burden · auditability 八项组件指标，并保留 paired scenario ordering 以支持 model / policy 对照。我们在 120 sovereignty stress scenarios × 4 模型家族 × 8 policy baselines 上评估，产出 3,840 冻结提示轨迹——包含 raw prompts / outputs / provider-form responses / parsed actions / recomputable metrics / hard-set analyses / qualitative cases / 240 items 的 3 位盲审。Full-sovereign 脚手架在 sovereignty score 上全面超过 direct · memory-only · consent-only · evidence-only · ReAct/tool-use · safety-prompt · judge-guard 七个基线，并同时降低 privacy leakage / consent violation / over-concession / manipulation capture。人工审计显示隐私 / consent 上高 agreement · manipulation 上低 agreement——揭示了平台劝服判断的主观前沿。这些结果说明：personal-agent 评估必须越过任务完成，走向representative · consent-aware · evidence-grounded action。

核心内容解读（问题 · 八轴度量 · ObservableState/HiddenLabels 分离 · 120 场景八类基线 · 人工审计 · 与 H2 benchmark 五联拍升级的定位）

问题背景。2024–2026 三年，personal agent 从"可行性 demo" 走向"持续存在的用户中介"——它们会长期记住用户偏好、过滤平台内容、代表用户使用工具与服务谈判。典型产品：Anthropic Claude 长期 memory · OpenAI ChatGPT memory feature · Rabbit r1 · Humane AI Pin · Meta Reality Labs · Google Astra · Adept。但既有 benchmark（Mind2Web / WebArena / OSWorld / WorkArena / AgentBench / GAIA）都在评估 tool use / navigation / task success——没有一个追问 agent 是否真正为用户站台。这里的沉默维度 是核心矛盾：personal agent 天生处于用户 vs 平台的利益张力中——比如 agent 帮用户订机票时，OTA 平台的操纵激励（联营酒店 upsell、动态定价、限时诱饵）会渗透进 agent 的推荐；agent 记录用户偏好时，隐私边界（哪些 preferences 可以传出去）没有标准；agent 帮用户谈判时，consent 边界（哪些决策要用户确认、哪些可以自主）没有明确指标。SovereignPA-Bench 正是这场沉默维度 的第一份可执行 benchmark。

八轴度量的结构。作者提出的八个度量分成能力侧 × 主权侧 两大簇：

簇轴核心问题
能力侧Task success是否完成用户交给的任务
能力侧Alignment是否推进用户当前 意图（不是过去 意图的静态复读）
主权侧Privacy是否只共享必要最小 用户信息 · 是否泄露 sensitive 数据
主权侧Consent是否在超出授权范围前征求 用户 consent
主权侧Evidence是否为推荐 / 决策展示证据（可回溯）
主权侧Manipulation是否抵抗平台化操纵激励（诱饵、锚定、损失厌恶利用）
主权侧Burden是否合理管理用户决策负担（不过度询问、也不隐藏关键选择）
主权侧Auditability是否留下可审计 的行动轨迹（用户可以回溯、验证、纠错）

这八轴合起来定义了什么叫"为用户服务"的 agent——不是"完成任务分数最高"，而是八轴维度合力 maximize。这是 2026 H2 personal agent evaluation 的价值观基础。

ObservableState × HiddenLabels 分离——benchmark 方法学新范式。之前的 agent benchmark 常常出现信息泄露：评估的 ground truth 会隐式暴露在 prompt 里（e.g. "请找出最便宜的机票" 已经暴露"价格最优" 是 evaluator 关注的），agent 可以猜到 evaluator 要什么，从而过度拟合 评委意图。SovereignPA-Bench 严格分开两侧：ObservableState 是agent 能看到的——用户当前发言、可见环境、历史 preferences、tool response；HiddenLabels 是evaluator 独占——用户的隐藏真实利益、隐私风险等级、平台的操纵企图、consent 违反标记。这个分离让 agent无法猜出 evaluator 意图——只能凭借自身对 sovereignty 的内化理解 去行动。这是继 7-06 AgentLens（hidden representation 分离）之后，H2 又一个"hidden 侧" 方法学。

120 场景 × 4 模型家族 × 8 policy baseline 网格。Baseline grid 覆盖了 personal agent 领域所有主流范式：

  • Direct：裸模型直接回答——最弱基线，无任何 sovereignty 意识。
  • Memory-only：仅有 preferences memory，无其他 sovereignty 组件。
  • Consent-only：仅在超授权时询问，其他方面无强化。
  • Evidence-only：仅要求为决策展示证据，其他方面无强化。
  • ReAct / tool-use：经典 ReAct 范式——推理 + 工具调用循环。
  • Safety-prompt：System prompt 加安全指令的 chatbot-era 做法。
  • Judge-guard：加装 judge model 做行动前过滤。
  • Full-sovereign：全组件——本文提出的完整脚手架。

这 8 个 baseline 是 sovereignty 组件的 2^3 完全组合（memory × consent × evidence 三 boolean 拉 8 格）加上外围 ReAct / judge-guard——干净的 ablation grid。Full-sovereign 战胜所有 7 个基线 的结论说明：sovereignty 是一个 emergent 组合能力，单一组件（memory / consent / evidence）不能替代——必须全组件叠加。

人工审计的诚实。3 位盲审标注员在 240 items 上给出的 agreement 数据非常关键——作者诚实报告：privacy 和 consent 上高 agreement（说明这两轴有清晰标准），manipulation 上低 agreement（说明"什么是平台操纵" 是 subjective frontier）。这个诚实的 disclosure 让 benchmark 有了健康的健康报告——不是虚假宣称"八轴都高置信"，而是公开哪几轴还需要方法论发展——这与 7-03 Necessary but Not Sufficient 的诚实报告 grader 非确定性 属于同一学术精神。

H2 benchmark 方法学的新升级——从五联拍到六联拍。之前的 H2 benchmark 五联拍关注benchmark 内在质量——物品 (IRT) · 搜索 (BOA) · 评委 (Grader-Repro) · 构造 (TASTE) · 配置 (SafetyRepro)——本文补上第六联：user-sovereignty 价值观维度——把 benchmark 谱系从"技术侧 reliability" 扩展到"用户利益侧 representativeness"：

对你三个研究方向的启发
Harness Engineering

(1) ObservableState × HiddenLabels 分离是 harness 方法学——不只是 benchmark，任何 harness 系统都应该严格分离 agent 可见 state 和 evaluator 可见 label——这是防止 harness 内部数据泄露污染评估的硬约束；你毕设做 SGLang KV-cache 优化时也应严格分离："KV-cache 策略可见的信息" vs "评估者独占的 ground truth"——例如 cache-hit rate 是 observable，correctness label 是 hidden；(2) 八轴度量的 harness 化——本文八轴中至少四轴（privacy · consent · evidence · auditability） 可以在 harness 层用结构化 hooks 直接测量：privacy 用信息流追踪、consent 用确认对话计数、evidence 用citation extraction、auditability 用action log completeness——你可以做 SovereignHarness——把八轴度量打包成 harness 中间件；(3) 与今日 harness 报告 evalci 的组合：八轴 × evalci 统计层——每一轴都单独做 CI + 显著性 + 多重比较修正，比 raw 平均分严谨得多；(4) 与 7-02 Loop Engineering 的Loop Specification 五元组的组合：把八轴度量作为 loop 的verification ladder 输入——loop 停止条件之一可以是"sovereignty score 达标"；(5) 3,840 冻结提示轨迹是典型的 batched harness workload——SGLang prefix caching 天然可以加速这种同 prompt 前缀多模型跑 的评估——你可以做 "SGLang-Sovereignty-Bench Runner"，让 3,840 trajectory 从几小时降到几十分钟；(6) 长期看，personal agent 评估将是 harness 系统的下一大批量客户——SGLang / vLLM / TGI 之类的推理服务应该内置 SovereignPA-Bench runner。

Agent Skills Safety

(1) Sovereignty 是 agent safety 的用户侧对偶——传统 agent safety 关注"agent 不做坏事"（禁止侧）；sovereignty 关注"agent 真为用户站台"（推进侧）——两者正交：agent 可以是完美安全（不做任何危险 tool call）但完全不主权（对平台操纵毫无抵抗）；agent 也可以是完全主权但不安全（为用户不惜违反隐私规则）——H2 应该有"safety-sovereignty 双轴 leaderboard"；(2) 与今日 agent-safety 报告 Autoformalization / Policy-as-Code 的深度组合：Cedar policy 可以形式化编码八轴度量的约束——把 sovereignty 变成 machine-checkable policy——H2 可以做 "Sovereignty-as-Code" 产品；(3) 与 6-30 Agent Safety Is Action Alignment 外置派的深度组合：Action Alignment 说"agent 应该被拒绝错误 action 而非拒绝 input"——本文补上"什么算错误 action" 的答案：违反 sovereignty 八轴 就是错误 action；(4) 与 7-06 AgentLens 可解释派的组合：AgentLens 检测"agent 有害执行状态"——本文可以扩展 AgentLens 检测"agent 主权失守状态"——例如"正在被 upsell 诱饵捕获"——用 hidden representation 中的 subspace steering 抗操纵；(5) Skill-facing manipulation risk：如果 skill 描述被平台方污染（e.g. 一个 travel skill 内嵌 OTA 优先推荐），本文的 manipulation 轴可以直接测量——这是 SkillSafetyBench 的姊妹 attack surface；(6) 长期看，personal agent 会是manipulation 攻击 的最大 target——本文八轴中的 manipulation 轴会成为 2027 年的 first-class safety topic——本文是这个议程的议程 setter；(7) 立即可创建的融合产品：Sovereignty-Cedar-BOA 三件套 —— Cedar 编码八轴 policy · BOA 搜索 unsafe/unsovereign trajectory · SovereignPA-Bench 提供数据集——是 H2 personal agent safety 的完整闭环。
