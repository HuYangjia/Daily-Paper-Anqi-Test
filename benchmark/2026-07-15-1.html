一句话核心贡献
Replay 三大公开 agent benchmark 首次量化 partial-evaluation 的科学门槛 —— AppWorld 15%、tau-bench 25%、SWE-bench Verified 90%——不同 benchmark 相差 6 倍以上。
摘要翻译（忠实原文）

Agent benchmark 常常在所有任务运行完毕后比较两个 agent，但昂贵的评估成本 让"跑部分任务" 成为一个诱人的捷径。仅仅报告 task fraction 并不能证明"部分预算跑" 是否支持与"完整 benchmark" 相同的成对比较结论。我们通过重放 SWE-bench、AppWorld、tau-bench 上已完成任务的 task-level 记录 来研究这个问题。一个部分预算 只有当它同时满足以下三个条件时才算 "足够"：(1) 支持与完整 benchmark 相同的决策 · (2) 覆盖所需的任务组 · (3) 让未定论 (unresolved) 的成对比较不超过目标比例。所需的 task fraction 差异剧烈——在 严格 0 pp（percentage point）门槛 + 5 pp 预算网格 下：AppWorld 首次达标 15%、tau-bench 25%、SWE-bench Verified 90%；SWE-bench Lite 在主要覆盖规则 下即使到 95% 也未达标。Partial-evaluation 报告应当明确五件事：(1) agent A 需要以多大差距超越 B？(2) 任务如何抽样？(3) 需要什么覆盖规则？(4) 使用什么决策规则？(5) 允许多少成对比较悬而未决？

核心内容解读（约 590 字）

问题背景：2026 H2 agent benchmark 生态最大的经济学矛盾——agent 评估越来越贵（每个 SWE-bench 任务可能烧几美元 API + 分钟级 wall clock），而每一位研究者都要在自家论文里"跑一遍完整 benchmark"。业内流行的暗地做法是"先跑一小部分 tasks 看看再说"，但没人系统回答过一个基本问题：跑 15%、跑 30%、跑 50% 是否足够支持"A 优于 B" 的结论？既有的 partial-evaluation 论文往往含糊报告"我们采样了 N tasks"——但采样多少、以什么规则、允许多少 pairwise 结论悬空，全没交代。这就构成了 agent 评估的科学性危机：任何论文的比较结论都可能被"预算不足" 无声反转。

核心方法：Replay + 三条硬门槛。作者采用元评估（meta-evaluation）策略——不重新跑 benchmark，而是重放已完成的 task-level 公开记录（SWE-bench、AppWorld、tau-bench 都开放了 task-level 结果）。定义 "部分预算 = 足够" 的三条 sufficient conditions：(1) Decision-preserving——部分预算的成对比较结论必须与完整 benchmark 一致；(2) Coverage——覆盖 benchmark 内所有必要 task group（如 SWE-bench 里的不同代码库、tau-bench 里的不同域）；(3) Unresolved limit——允许一部分成对比较悬而未决，但不能超过目标比例。评估设计：严格 0 pp 门槛（partial 与 full 的决策必须完全一致）× 5 pp 预算网格（从 5%、10%、15% ... 逐步增加），看每个 benchmark 首次全部达标的预算。

结论与突破：不同 benchmark 的 partial-evaluation 门槛差异达 6 倍以上——AppWorld 15% 就够，tau-bench 25% 就够，SWE-bench Verified 却需要 90%，SWE-bench Lite 甚至到 95% 都未达标。这个结果反直觉地重要：benchmark 的"效率" 与"任务集大小" 弱相关——SWE-bench Lite 明明是 Verified 的精简版，反而更难被 partial-evaluation 支持。原因深藏在task-level agent 表现的"方差结构"：如果 benchmark 内 tasks 的难度分布高度异质、agent 之间的 win-loss 结构复杂，那 partial 采样很难重现整体决策。

H2 benchmark 谱系再拓展一格：第十五联 · Partial-Evaluation Discipline 联（部分预算评估纪律联）——十四联"Skill-Following Reliability 联"（今日 SLBench）+ 十三联"Held-Out + Budget-Matched 联"（今日 Rethinking Harness Evolution）+ 十二联"Language Sovereignty 联"（7-14 K-BrowseComp）+ 十一联"Unified Red-Team 联"（7-13 REALM）+ 十联"文化联"（7-10 Pluralis）+ 本文 Partial-Evaluation Discipline 联。五要素报告规范可以像 Datasheets for Datasets / Model Cards 一样成为 agent benchmark 论文的提交必备附件——这是 agent benchmark 走向可复现工程 的又一颗关键螺丝。

Partial-Evaluation 报告五要素规范 —— 应像 Model Card 一样标准化
要素需要回答的问题为什么关键
1. MarginAgent A 需以多大差距超越 B 才算显著？决定"多小的差距不值得下结论"
2. Sampling RuleTasks 如何抽样？（随机 / 分层 / 目标 group 覆盖）不同抽样规则会得到不同的 partial 结论
3. Coverage Rule需要覆盖哪些 task group？覆盖到什么粒度？SWE-bench 有代码库分层，tau-bench 有 domain 分层
4. Decision Rule使用什么规则做成对决策？（pairwise 胜率 / statistical test / effect size 阈值）不同决策规则的 partial 效率不同
5. Unresolved Budget允许多少成对比较"悬而未决"？这是 partial 评估的 honesty budget —— 承认部分比较无法定论

与 7-15 harness 报告的"匹配预算" 呼应：本文提供 benchmark-side 的预算规范，7-15 harness 报告（Wang/Hajishirzi/Tsvetkov）提供 method-side 的预算规范。两侧同时纪律化才能让 agent evaluation 走向科学。

对研究方向的启发
对 Benchmark

H2 benchmark 谱系再拓展一格 · 第十五联：Partial-Evaluation Discipline 联（部分预算评估纪律联）——文化联（Pluralis, 7-10）+ Unified Red-Team 联（REALM, 7-13）+ Language Sovereignty 联（K-BrowseComp, 7-14）+ Held-Out + Budget-Matched 联（Rethinking Harness, 今日）+ Skill-Following Reliability 联（SLBench, 今日）+ 本文 Partial-Evaluation Discipline 联。方法学可复用：(1) Replay 分析——不重跑 benchmark，而是重放 task-level 记录；零额外算力成本；(2) 三条 sufficiency conditions（decision-preserving / coverage / unresolved limit）——任何 partial-evaluation 论文都可以套用；(3) 5 pp 预算网格 + 严格 0 pp 门槛——为 benchmark 设计者提供了校准新 benchmark 是否"适合 partial-evaluation" 的元指标；(4) 五要素报告规范——应像 Model Card / Datasheets 一样成为 agent benchmark 论文的强制附件。下一步预测：Partial-Evaluation Discipline 会向"benchmark-side auto-recommender" 演化——benchmark 发布方主动提供"跑 X% 就够" 的官方推荐值 · benchmark 论文提交 CI 里直接接入本文的 replay 检查。

对 Harness Engineering

本文与今日 Harness 报告"Rethinking the Evaluation of Harness Evolution" 构成双联规范：Wang/Hajishirzi 组管 method-side 预算（harness 方法需报告 feedback + inference budget），Huang 管 benchmark-side 预算（benchmark 需报告 partial 门槛）——两者结合让 agent 评估的两端都有可复现性纪律。启发：(1) harness 论文应报告"benchmark partial-evaluation coverage"——如果一篇 harness 论文只跑了 SWE-bench 20%，本文数据告诉你这不够，作者应该把结论声明降级为"探索性"；(2) benchmark-side 预算表可以成为 harness evolution 论文的补充测试点——不同 harness 在不同 partial 预算下的表现可作为 robustness 指标；(3) 与 今日 harness 方向 (Wang et al., UW+AI2) 呼应——两论文同日提交、同时管理 method + benchmark 两侧预算，构成agent 评估科学化的双子星。

对 Agent Safety

Safety benchmark 也急需 partial-evaluation 校准——safety benchmark 通常包含大量 attack case（HarmBench 400+、SafetyBench 千级），跑一次很贵。本文方法学可以直接迁移：(1) safety benchmark 应重放已完成 task-level 记录——评估其"partial-evaluation 门槛"；(2) unresolved budget 概念对 safety 特别重要——某些 attack 是否被防守成功可能模棱两可，safety 评估应明确允许多少"悬而未决"；(3) 与 今日 agent safety 报告 SLBench (Chen, Wang, Yan, Zhang @ Purdue) 呼应——SLBench 只有 86 case（本征小规模），若应用本文规范，可能发现"跑 20-30 case 就足以判定 A vs B"——为企业级 safety 审查提供成本节省依据；(4) 长远看——safety benchmark 的 partial-evaluation discipline 会影响 AISI 类监管机构的审查协议——他们必须回答"跑了多少 case 才敢下结论 model X 通过 safety review"。
