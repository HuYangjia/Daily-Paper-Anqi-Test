一句话核心贡献
为 agent benchmark 的"部分预算 evaluation" 建立三条硬门槛 + 五要素报告规范——replay 三大公开 benchmark 揭示 required task fraction 差 6 倍以上（15% vs 90%）；KDD 2026 Workshop 认可。
摘要翻译（忠实原文）

Agent benchmark 通常在所有任务跑完之后 比较两个 agent，但高成本评估 使得部分执行（partial runs）成为常见诱惑。然而任务比例本身并不足以说明 partial run 是否支持与完整 benchmark 相同的 pairwise 结论。我们通过 replay SWE-bench · AppWorld · tau-bench 三大公开 benchmark 已完成的task-level 记录研究这一问题。

Partial budget 只有满足以下三个条件才算"足够"：(1) 支持完整 benchmark 的决策结论（decision-preserving）· (2) 覆盖必需的任务组（coverage requirement）· (3) 未决 pairwise 对比不超过目标比例（unresolved limit）。

Required task fraction 变化剧烈。在严格 0 pp 阈值 + 5 pp 预算网格 下：AppWorld 首次达标 15%、tau-bench 达标 25%、SWE-bench Verified 达标 90%；SWE-bench Lite 在主 coverage rule 下 95% 仍未达标。不同 benchmark 之间的差距超过 6 倍——同样"部分评估" 在 AppWorld 上跑 15% 就够，在 SWE-bench Lite 上跑 95% 也不够。

Partial-evaluation 报告应明确声明 五要素：(1) 一个 agent 必须比另一个高多少（outperformance margin）· (2) 如何选择任务（task selection）· (3) 采用什么覆盖规则（coverage rule）· (4) 采用什么决策规则（decision rule）· (5) 可以留下多少未决对比（unresolved comparisons）。这五要素合成 agent benchmark partial-budget 报告的最低方法学门槛。

核心内容解读（约 620 字）

问题背景：过去两年 agent benchmark 走向"高成本 evaluation" 的深水区——AppWorld 每 task 数分钟工具交互 · SWE-bench Verified 每 task 数十分钟 IDE 交互 · tau-bench 双方 LLM 对话。一次完整 benchmark 评估动辄消耗几万美元 API 调用 + 数天时间——工业界普遍做法是只跑部分任务就下结论："我们在 AppWorld 30 个任务上跑了，比 GPT-4 高 5 pp"。这类 partial-budget 报告目前缺乏方法学门槛——什么算够？作者提出：任务比例本身不足以决定，必须满足三个条件才算"partial 足以支持完整结论"：(1) partial 决策与完整 benchmark 一致；(2) 覆盖必需任务组（避免只挑简单任务）；(3) 未决 pairwise 对比数量在阈值内。这三条件构成本文核心方法学贡献。

方法：Replay 三大 agent benchmark。作者利用 SWE-bench · AppWorld · tau-bench 已公开的 task-level 完整记录（每个 task 的每个 agent 是否成功）进行模拟部分预算——对于任意 partial budget（5%, 10%, ..., 95%）与任意任务采样方式，可以精确 replay 出"如果我们只跑这个 partial 预算，结论会与完整 benchmark 一致吗？"。作者构造 5 pp 网格上 0-95% 的完整扫描，报告首次达到"三条件全部满足" 的 partial fraction。评估的pairwise 对比对象 是 benchmark 中所有 agent 两两比较，因此是决策一致性 而不是分数一致性——更贴近真实场景（工程师问的是"A 是否好于 B"）。

三大关键发现：(1) benchmark 之间差距巨大——AppWorld 只需 15%、tau-bench 需 25%、SWE-bench Verified 需 90%、SWE-bench Lite 95% 都不够——一个 benchmark 需要的 partial 比例可能是另一个 benchmark 的 6 倍以上；(2) 差距背后的机制：AppWorld 与 tau-bench 的任务难度分布均匀——sample 15% 就能刻画 pairwise 决策；SWE-bench Verified 与 Lite 的难度分布 heavy-tailed——少数难任务承担了大部分区分度，缺任何一个都导致决策翻转；(3) SWE-bench Lite 95% 未达标——甚至跑到 95% 都不能保证与完整一致的决策——这一发现颠覆 了工业界"95% 就是几乎跑完" 的默认预设，说明该 benchmark 不适合部分预算模式——只能全跑或不跑。

Partial 报告五要素规范：作者进一步提出所有 partial-evaluation 报告应显式声明五个字段：margin（A 必须高于 B 多少）· selection（如何采样任务）· coverage（覆盖规则）· decision（决策规则）· unresolved（可留未决对比上限）。这五要素成为 KDD 2026 agent benchmark 方法学门槛——未按此规范的 partial 报告将被视为不可复现。H2 benchmark 方法学第十五联：Partial-Evaluation Discipline 联——从"跑全部" 或"跑一部分" 的二选一抬到"跑一部分，但必须说明五要素"。

Benchmark首次达标 partial fraction与完整 benchmark 决策相符解读
AppWorld15%三条件满足难度分布最均匀 —— partial-budget A/B 首选
tau-bench25%三条件满足难度分布较均匀 —— partial-budget 可接受
SWE-bench Verified90%三条件满足heavy-tailed 难度——partial-budget 极限接近完整
SWE-bench Lite> 95%主 coverage 规则下 95% 仍未达标不适合 partial 模式——只能全跑或不跑

核心洞察：partial-budget 可行性是 benchmark 的结构属性，不是使用者的选择；同一 partial fraction 在不同 benchmark 上有本质不同含义——15% AppWorld 报告是"决策级充分"，15% SWE-bench Lite 报告是"决策级无意义"。agent benchmark 设计者今后应显式报告 benchmark 的 partial-budget 可行性，让使用者知道"这个 benchmark 是否可以部分跑"。

Partial-Evaluation 报告五要素规范 · agent benchmark 方法学新门槛
要素字段名必须回答缺失后果
1 · MarginOutperformance marginA 必须比 B 高多少才算"胜出"？无法解释统计显著性 · 无法比较不同 partial 报告
2 · SelectionTask selection strategy如何采样任务：random / stratified / adversarial?存在挑简单任务的樱桃采摘 风险
3 · CoverageCoverage rule必须覆盖哪些任务组 / 分类？缺覆盖导致 domain generalization 失效
4 · DecisionDecision rule基于什么规则宣布 A 胜出？随意选择导致 selective reporting
5 · UnresolvedUnresolved-comparison budget可以留下多少 pairwise 未决对比？关键新概念——承认 partial 无法解决所有对比是方法学诚实

方法学贡献：Unresolved-comparison budget 是本文最新颖的概念——传统 evaluation 假设所有对比都能决出胜负，本文明确承认"partial-budget 下部分对比留白" 是合理的，只要留白比例在预算内。这与 statistical inference 里"接受未拒绝零假设" 精神一致——不能强行下结论就是方法学诚实。

Rethinking the Evaluation of Harness Evolution for Agents（7-15 我们的 Harness 报告，2607.12227）· arxiv.org/abs/2607.12227 —— UW + AI2 的harness 层评估协议批判；与本文构成 "agent evaluation 方法学双子星"——一位关注 harness 层公平（匹配预算 + held-out），一位关注 benchmark 层公平（partial-budget 五要素）；两篇合成 2026 H2 agent evaluation 走向科学化的关键突破。

对研究方向的启发
对 Benchmark

H2 benchmark 方法学再拓展一格 · 第十五联：Partial-Evaluation Discipline 联（部分预算纪律联）——物品侧信息量（7-02 IRT）+ 搜索侧覆盖率（7-03 BOA）+ 评委侧稳定性（7-03 Necessary but Not Sufficient）+ 构造侧代表性（7-03 TASTE）+ 配置侧完整性（新）+ 价值观侧对齐（新）+ 本文 预算侧纪律。方法学立刻可复用：(1) Benchmark 应公开 partial-budget 可行性——所有 agent benchmark 应报告 required task fraction @ 0 pp / 5 pp / 10 pp threshold——像 dataset card 一样成为标配；(2) partial 报告五要素强制字段——KDD 2026 workshop 已经把它变成方法学门槛，未来 NeurIPS / ICML / ICLR benchmark track 会 follow；(3) benchmark 分类——partial-friendly (AppWorld 类) vs partial-hostile (SWE-bench Lite 类)——工程师可根据 A/B 需求选择合适 benchmark；(4) Unresolved budget 是新一等公民——允许"部分未决" 是方法学诚实；(5) H2 benchmark 谱系第十六联预测：Cost-adjusted Score 联（把 partial budget 与美元 / GPU-hour 挂钩）—— 与 Writer AI 7-09 harness 经济学层相呼应。下一步预测：SWE-bench 团队会官方发布 partial-budget 可行性数据——因为 Lite 95% 未达标这一发现会引发大量 partial-budget 报告的方法学质疑。

对 Harness Engineering

本文的"部分预算方法学" 对 harness engineering 有直接迁移价值：(1) harness 的 verifier gate 数量选择——不同任务 required gate count 差 6 倍以上（类比不同 benchmark required task fraction 差 6 倍以上），harness 设计者应按任务类型自适应 而非一律"多加 gate"；(2) harness 层五要素规范——本文的 5 要素可迁移为 harness partial-evaluation 报告规范：margin · selection · coverage · decision · unresolved；(3) 与 今日 Harness 报告 Partially Correlated Verifier Cascades (Han, 2607.13918) 呼应——Han 提供 verifier 层部分预算的相关性理论，本文提供 task 层部分预算的实证；两者合成 agent evaluation "部分预算" 完整理论 + 实证栈；(4) harness 应自动生成 partial-budget audit——把 5 要素报告嵌入 harness output 而非事后补充。

对 Agent Safety

本文"partial-budget 纪律" 对 agent safety 评估的直接借鉴：(1) safety benchmark 也是 heavy-tailed——AIR-Bench · HarmBench 都存在少数难攻击类别承担主要区分度——safety 评估的 required partial fraction 可能比 SWE-bench Lite 还高；(2) safety partial 报告必须声明五要素——尤其 coverage rule——不能只挑简单攻击类别，需要覆盖 red-team category 全谱；(3) 与 今日 Agent Safety 报告 Operational Reframing (Liu et al., 2607.07097) 呼应——Liu 提出 factorial 5 条件对照 · 本文提出 partial-budget 5 要素；两者合成 agent safety 评估的双 5-要素方法学门槛——机制维度 5 条件 × 预算维度 5 要素；(4) safety 应报告 unresolved comparisons——承认"某些 attack-defender 对比在 partial budget 下无法决出" 是方法学诚实；(5) H2 agent safety 谱系第十五派预测：Budget-Discipline 派——把 Huang 的 partial-budget 纪律直接迁移到 safety benchmark 世界。
