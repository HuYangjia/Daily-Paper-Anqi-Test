摘要翻译（忠实原文）

Digital Adoption Platform (DAP) 是 web 系统上广泛使用的嵌入式覆盖层——引导用户完成页面内操作、帮助他们快速上手陌生界面。然而完成真实任务很少只是在单一页面上点几下按钮——它需要在不断变化的页面状态 上展开一系列动作。

此前的研究还把 web agent 自动动作 与引导文本生成 视为两个独立问题，且大多数工作输入模型的是 DOM 或可访问性树等文本页面表征，而不是人类实际操作的渲染屏幕。

本文引入 MAG——首个把任务执行与引导撰写统一为单一 Multimodal Action and Guide 任务 的 benchmark，配套两种截图 grounding 方案：Set-of-Mark 元素选择 和原始像素坐标。我们进一步构建了该复合任务的完整 harness——覆盖 LLM 辅助标注 + 人工验证 · 训练 · live 环境评估 · action + guide 联合指标。

用该 harness 我们评估了前沿 API 模型 与开源多模态模型，并给出详细分析。最后我们设计了一种GRPO 训练方法——专家轨迹增强——使 9B 监督式 agent 的成功率几乎翻倍（从 6.9% 提升到 13.2%），同时提升引导质量。即使最强模型完成任务不到 40%——为未来研究留下充分空间。

核心内容解读（约 620 字）

问题背景：过去两年 web agent 与 DAP 是两条独立技术路线——web agent 学界（WebArena · WebShop · SeeAct）研究"agent 如何自动完成 web 任务"，DAP 工业界（WalkMe · Whatfix · Appcues 每年 $10B+ 市场）研究"如何在 web 页面上叠加 onboarding 引导" ——两条路线的评估集也几乎不重叠。作者指出这是一个方法学错位：DAP 引导文本本质上是 web agent 完成任务时留下的"人类可读注释"，二者应统一为同一任务——agent 完成任务 + 同时生成引导，因为二者在部署时是不可分割的。这一统一带来的 benchmark 是 MAG (Multimodal Action & Guide)。

方法学突破一：完全基于截图的 grounding。过去 web agent 主流做法是把 DOM 或 accessibility tree 喂给 LLM——文本化的页面表征简单但与人类操作方式脱节。MAG 反其道而行——完全只给渲染截图——设计两种 grounding scheme：(1) Set-of-Mark：预先在截图上标记可交互元素编号，agent 输出"点第 12 号" · (2) 像素坐标：agent 直接输出 (x, y) 坐标点击。两方案覆盖 web agent 领域两大 grounding 派系（SoM 派 vs Coordinate 派），提供公平对比平台。方法学突破二：完整 harness 生态——不仅是一个静态数据集，而是包含LLM 辅助标注 + 人工验证（保证 ground truth 可信）、训练管道（专家轨迹格式、GRPO 集成）、live 环境 evaluation（真实浏览器执行）、联合指标（action 成功率 + guide 质量分数）——这是 benchmark + harness 一体化 的完整生态。

方法学突破三：GRPO + 专家轨迹训练。作者不满足于"提供 benchmark 让别人跑分"，主动示范如何训练——采用 Group Relative Policy Optimization (GRPO, DeepSeek 系列 RL 方法) + 专家轨迹增强——9B 监督基线成功率 6.9% → GRPO 训练后 13.2%（几乎翻倍）——同时 guide 质量提升。这一实证证明 MAG 不仅是评估工具，还是训练目标——是标准的 benchmark-as-training-signal 范式。

关键限制：即便最强前沿模型完成率仍不足 40%——说明 MAG 的难度上限 远未被触及。这是一个健康的 benchmark 特征——饱和头顶留白，为未来 2-3 年的研究提供改进空间。H2 benchmark 谱系新增第十六联：Task Unification 联（任务统一联）——把之前"agent action-only" 与"guide-only" 两个独立评估合成为联合评估；哲学突破：agent benchmark 应该模拟部署场景中不可分割的复合任务，而不是把它们拆成学术子问题分别评估。

核心观察：MAG 的三大突破合起来 才是它真正的价值——单一维度突破（如"只做截图 grounding"）过去也有工作做过（如 SeeAct, WebGUM, GUI-Owl），但把"任务统一 + 纯截图 grounding + 一体化 harness + 训练示范" 四件事同时做好——这才是 MAG 作为 2026 H2 benchmark 代表作 的原因。

对研究方向的启发
对 Benchmark

H2 benchmark 谱系再拓展一格 · 第十六联：Task Unification 联（任务统一联）——七联图（物品 / 搜索 / 评委 / 构造 / 配置 / 价值观 / 部分预算纪律）+ 本文 任务统一联。方法学立刻可复用：(1) 独立子任务应先检查"部署时是否可分割"——不可分割的必须统一评估（web action + guide 是典型不可分割例）；(2) 多模态融合任务的 grounding 双方案——为不同派系提供公平对比平台（避免"SoM 只跑 SoM benchmark、Coordinate 只跑 Coordinate benchmark"的孤立比较）；(3) Benchmark + Harness 一体化生态——不再提供单纯静态数据集，而是包含标注 / 训练 / live 评估 / 联合指标四件套；(4) 训练示范包在 benchmark 内——MAG 主动公开 GRPO + 专家轨迹训练管道，让 benchmark 兼作 training signal；(5) H2 benchmark 谱系第十七联预测：Live Environment Coupling 联——把 live 浏览器 / OS / device 环境作为 benchmark 的一等公民，取代静态记录的模拟评估。下一步预测：WebArena / SeeAct / GUI-Owl / OSWorld 团队会 follow MAG 加入 guide 生成子任务，因为 DAP 市场直接消费 —— 学术 benchmark 走向产业融合 的关键案例。

对 Harness Engineering

MAG 是 benchmark 与 harness 一体化的典范——直接为 harness engineering 提供以下启发：(1) harness 应主动包含 evaluation 管道——不能只做 agent 执行，还要负责结果收集、联合指标、live 环境验证；(2) 与今日 Harness 报告 Partially Correlated Verifier Cascades (Han, 2607.13918) 呼应——MAG 的联合指标（action + guide 双裁判）天然存在相关性——Han 的 Beta-Binomial NPMLE 可用于校准；(3) harness 应内置 GRPO 训练管道——benchmark-as-signal 需要 harness 承担 RL 训练接口；(4) H2 harness 谱系第十四层预测：Benchmark-Integrated 层——把 benchmark 的评估管道直接嵌入 harness · 从"harness 输出结果 → benchmark 计分" 抬到"harness 就是 benchmark 的执行时"。

对 Agent Safety

MAG 的方法学对 agent safety benchmark 有直接迁移价值：(1) safety 与 capability 应联合评估——像 MAG 把 action 与 guide 统一那样，safety benchmark 应把capability + safety 联合评估（今日 Operational Reframing (Liu et al., 2607.07097) 已经启动 factorial 对照，MAG 提供联合指标模板）；(2) live 环境部署——safety 评估不能只在静态 prompt 上跑，需要 MAG 式的 live 环境 harness；(3) H2 agent safety 第十六派预测：Live-Environment Safety 派——safety 评估进入真实浏览器 / OS / device——与今日 agent safety 报告的机制分离方法学 合力构建agent safety 在实际部署环境中的可信评估协议；(4) skill safety × MAG 融合——7-15 SLBench (Purdue) 提供 skill 内部逻辑关系评估，MAG 提供 live 环境执行验证——两者合并可构建"skill 内部安全 + skill 执行安全" 联合基准。
