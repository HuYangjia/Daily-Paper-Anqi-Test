一句话核心贡献
首个把多语言性 作为 first-class 变量、量化 LLM agent 在long-horizon workflow 中compounding 衰减 的 benchmark。
摘要翻译（忠实原文）

LLM agent 在需要规划、工具使用和与外部环境交互的长程任务上表现强劲。然而，大多数现有 benchmark 隐式假设单语设置——即整个执行过程（包括推理、工具调用和输出生成）都在单一语言内进行。与此相对，现实应用经常在同一工作流中涉及多语言输入和输出，而多语言性与 agent 执行之间的交互仍然被欠探索。本文引入 PolyWorkBench，一个评估 LLM agent 在多语言长程职场工作流 的 benchmark。PolyWorkBench 包含 67 个跨 5 个 domain 的任务，涵盖 commerce（商务）· knowledge work（知识工作）· legal analysis（法律分析）· localization（本地化）· manufacturing（制造），agent 必须处理异质的多语言输入、进行迭代推理、调用外部工具，并产出结构化输出。为了实现全面评估，我们提出一个混合评估框架，结合结构化打分（structural grading）· 可执行验证（executable verification）· 基于 LLM 的语义评估（LLM-based semantic assessment） 三部分。该设计能够跨复杂工作流同时捕捉功能正确性与语言一致性。实证结果显示，SOTA LLM agent 在多语言工作流设置下相对单语对照组出现显著性能衰减。我们的分析表明，多语言性沿推理与执行步骤引入 compounding effects——凸显在 agent 评估中联合建模语言变异与程序性决策 的重要性。

核心内容解读（500 字）

解决了什么问题：现有 agent benchmark（AgentBench · τ-bench · SWE-bench · AgentGym · WebShop）几乎全部是单语——推理链、工具调用、输出全部英文，或全部中文。但现实职场：法律工作者用英文合同、日文法规、中文批注；跨境电商 agent 处理西语用户查询 + 韩语供应商邮件 + 英文数据库；制造业本地化流程读中文规格、生成英语工程文档、发送多语通知。这三条工作流 与"单一语言 agent 反复自问自答"是本质不同 的任务分布。若 benchmark 完全屏蔽这一维度，leaderboard 上的高分几乎无法预测真实职场部署表现——这是agent 评估的隐藏系统性偏差。

核心方法：三件套。（1）67 tasks × 5 domain 覆盖——commerce（商务谈判、跨境订单处理）· knowledge work（多语文献综述、翻译审核）· legal analysis（多法域合同比对、法规映射）· localization（软件/文档本地化流水线）· manufacturing（跨语言规格→工艺文档转化）。每个 task 需要 agent 处理异质多语输入 + 迭代推理 + 至少一次外部工具调用 + 产出结构化输出。（2）Hybrid evaluation framework 三合一——Structural grading：输出结构是否符合模板（JSON schema · 表格字段 · 段落分节）；Executable verification：工具调用参数是否合法、返回值是否被正确消费、下游脚本能否成功执行；LLM-based semantic assessment：跨语言语义一致性（比如中文输入描述的合同条款是否在英文输出中被完整保留）。三部分设计使得功能正确性 × 语言一致性 同时可测。（3）Compounding effects 量化——多语言性不是"每一步下降 X%、总下降 X%"，而是推理阶段的语言错配 会污染工具调用参数、又进一步污染输出生成，产生合成型衰减。这一现象无法从单语 benchmark 或单步多语 benchmark 里观察到——必须是 long-horizon × multilingual 联合评估才能显现。

与现有工作的突破点：三条独立立场。（i）区别于 K-BrowseComp（2606.02404 · 韩语 web browsing benchmark）· KSAFE-MM（2605.28013 · 韩语文化多模态安全）——那些是单一非英语语言的替换式扩展；PolyWorkBench 是同一工作流内多语言混合，属于本质不同的 agent 任务分布。（ii）区别于 7-03 TASTE（反转构造派）· 7-06 SafetyRepro（配置派）· 7-07 SovereignPA-Bench（价值观派）—— 那些解决"物品质量 · 配置稳定 · 价值观维度"，本文引入语言变异 × 程序决策 的新自由度，是 benchmark 方法学的第七联：多语言联。（iii）与 7-02 IRT · 6-28 REALM 互补——IRT 精选高信息量 items（心理测量派），REALM 穷举扩大 item pool（穷举派），本文拓展 item 的语言维度，是同一 benchmark 经济学谱系的正交推进。

Manufacturing（制造）跨语言规格→工艺文档 · 供应链多语通知 · 质量报告转换规格语 × 工艺文档语 × 通知语

Hybrid evaluation 三合一细节：

  • Structural grading — 输出格式合规性（JSON schema · 表格结构 · 字段完整性）。对格式敏感任务（如本地化流水线）权重最高。
  • Executable verification — 工具调用参数合法性 · 返回值消费正确性 · 下游脚本可运行性。对 commerce/manufacturing 等强工具任务是主要评分基准。
  • LLM-based semantic assessment — 跨语义一致性（源语内容 vs 目标语输出）、指代保持、关键实体不丢失。对 knowledge work / legal analysis 权重最高。

实验结果与核心论点

1. 主要发现：SOTA agent 在多语工作流下显著衰减——摘要直接给出定性结论 "state-of-the-art LLM agents suffer significant performance degradation in multilingual workflow settings compared to monolingual counterparts"（具体百分点在正文表格中，PDF 二进制流未能解析，暂以 abstract 结论为准）。

2. Compounding Effects 结构性证据——摘要明确：多语言性引入的衰减沿推理与执行步骤复合，而非独立衰减。这意味着：

  • 第 1 步推理阶段的语言错配不会自愈，会污染第 2 步工具调用参数选择
  • 工具调用参数的语义漂移进一步扭曲第 3 步输出生成的目标
  • 因此总衰减 > 单步衰减之和 —— 这是 long-horizon × multilingual 特有现象

3. 三合一评估框架的必要性——单一评分模式（比如只看最终 F1）会把"功能正确但语义漂移"或"语义一致但结构违规"混为一谈。PolyWorkBench 的正交三维 分离让下游 diagnosis 成为可能，同时避免LLM-as-Judge 的单点失败（因为结构化打分 + 可执行验证提供了独立于 LLM 评委的证据）——与 7-03 Necessary but Not Sufficient（评委派） 的核心担忧完全对齐。

4. 5 个 domain 的现实代表性——commerce/knowledge/legal/localization/manufacturing 覆盖2024-2026 年企业 agent 部署主要场景，是 K-BrowseComp（web browsing 单一场景）· ToolFailBench（tool-use diagnosis 单一维度） 之外的横向扩展。

对研究方向的启发
对 Benchmark

H2 benchmark 方法学七联拍雏形：物品（7-02 IRT）· 搜索（7-03 BOA）· 评委（7-03 Necessary but Not Sufficient）· 构造（7-03 TASTE）· 配置（7-06 SafetyRepro）· 价值观（7-07 SovereignPA-Bench）· 多语言（本文）。多语言联是横向扩展 items 语言维度——与其他六联（纵向：item 质量、搜索、评委、构造、配置、价值观）正交。工程可复用点：（1）Hybrid three-way evaluation（结构 × 执行 × 语义）可以直接被 τ-bench、AgentBench、SWE-bench 借用；（2）Compounding effect 指标（推理漂移 → 工具漂移 → 输出漂移的复合衰减）是新的 benchmark 维度，可以量化"long-horizon 的深度"；（3）与 7-08 Doomed from the Start 组"benchmark 承诺认证 × recall 保证" 组合——PolyWorkBench 可以直接接入 recall-controlled probe cascade 得到"多语言工作流的算力节省 pareto frontier"。

对 Agent Safety

多语言 × long-horizon 揭示的compounding effects 有直接的 safety 含义：（1）Safety policy 语言漂移风险——如果 policy 是英文写的但 agent 处理中文/日文输入，policy 的解释边界会漂移；7-07 Cedar Policy 派需要显式处理多语言 authoritative 版本；（2）Consent / manipulation 的多语言表现差异——与 7-07 SovereignPA-Bench 的manipulation capture 指标结合，可以研究"agent 在非母语场景是否更易被 prompt injection"；（3）Cross-language tool description 攻击面——MCP 工具描述以某种语言写，用户以另一种语言下达指令，可能出现7-05 Forged Reasoning Attacks 类型的漂移利用。方法学建议：把 PolyWorkBench 的 hybrid three-way evaluation 接入 agent safety benchmark，形成 "safety × multilingual × workflow" 三维矩阵。

对 Harness Engineering

PolyWorkBench 对 harness 层提出三条新工程要求：（1）Multilingual routing 内建于 harness 策略层——什么时候切换语言 · 什么时候统一到目标语 · 什么时候保持原文，应该是 7-08 Harness MDP 的七结构化动作 中新增的动作类型（本文的 4-6 hidden action：translate / normalize-language / preserve-original）。（2）Executable verification 与 harness 检查层集成——PolyWorkBench 的第二部分评估（工具调用可执行验证）正是 7-02 Loop Engineering Verification Ladder 的第二级 cheap-checks 的直接实现，两者天然融合。（3）Semantic assessment 是 harness 层新 rubric——用 LLM-based 跨语义一致性作为 7-03 Grader-Repro 派 的新评委输入。建议：把 PolyWorkBench 直接接入 7-08 Learning to Control Harnesses 的适配器体系，形成"learned multilingual harness controller"——这可以是 H2 下半年最值得追的跨谱系融合 研究方向。
