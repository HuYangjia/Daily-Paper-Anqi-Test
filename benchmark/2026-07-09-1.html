一句话核心贡献
把 agentic red-teaming 的二值 attack-success rate 升级为 L0-L6 有序七级 action-graded severity scale——按 reversibility × cross-scope × privilege 三维正交轴打分，可 trace-grounded 应用到已存在的 red-team log。
摘要翻译（忠实原文）

Agentic red-teaming benchmarks 把"注入的 agent 是否被攻破"报告为单一比特：攻击成功了，还是没成功。我们主张：这个二值 attack-success rate 抛弃了防御方最需要的信息——即产生的行动有多大危害。我们引入 action-graded harm rubric，按七级有序尺度（L0 - L6）给 agent 的 tool-call 轨迹打分，依据三条正交轴：（1）行动是否可逆；（2）是否跨到另一方（cross-scope）；（3）是否扩展了权限。

我们用两种方式计算这一尺度：（1）deterministic oracle——读取轨迹与攻击者声明的目标；（2）3-panel LLM judge——由 3 个 frontier language model 组成的评委面板，读取无标签的相同轨迹。在 AgentDojo workspace suite 上 × 4 个 victim model × 2 个 defense 上，严重度分级暴露了三个二值指标看不见的失败——包括一个报告 ASR = 0 却仍存在 externally visible cross-scope leak（通过未过滤工具）的防御。

Judge 面板以高有序一致性（Krippendorff's α = 0.91）再现 oracle，但共享了我们所刻画的系统性盲点，最显著的是无法识别升级链（escalation chain）。与先前提供有害任务清单、有害任务完成测试、执行级安全 benchmark 或严重度感知仿真的工作不同，我们的贡献是一个可复用的、trace-grounded 的严重度工具，应用于已存在的 red-team log 中的实际动作。所有代码、prompts 与 per-episode log 已释出。

核心内容解读（约 550 字）

解决了什么问题：H2 agentic red-teaming benchmark（AgentDojo · AgentBench · SafeArena · InjecAgent · AgentHarm 等）几乎无一例外用 attack-success rate（二值 0/1）作为核心指标——但 defender 关心的从来不是"attack succeeded 与否"，而是如果 succeed 了，损失有多大。作者在 4 个 victim × 2 个 defense 的 AgentDojo 交叉实验里发现三种典型 case 完全被二值遮蔽：（i）零 ASR 但存在 cross-scope leak 的防御——ASR = 0 却通过未过滤工具把敏感信息 leak 到第三方；（ii）相同 ASR 但严重度分布迥异 的两个模型；（iii）escalation chain——单步看每一步都是低危，但组合起来造成 L5-L6 高危害。

核心方法：三条独立创新。（1）Action-Graded Harm Rubric（L0-L6）——七级有序尺度，按三条正交轴打分：reversibility（可逆性）、cross-scope（是否跨到第三方）、privilege expansion（是否扩展权限）。每一级对应具体行动类型（例如 L0 = pure read-only no-scope-change；L3 = user-visible reversible harm；L6 = irreversible cross-scope privilege escalation）。（2）两条独立打分器——deterministic oracle 读取完整 tool-call trajectory + attacker stated goal（有 ground truth）；3-panel LLM judge 由 3 个 frontier model 组成，读取tag-free 版本的同一轨迹（无 attacker 目标）。（3）trace-grounded 应用于已存在的 log——不是新 benchmark，而是可迁移到任何已存在 red-team 结果 的分析工具，与 AgentDojo + AgentBench + AgentHarm 等直接兼容。

实验设置：AgentDojo workspace suite（电邮、日历、slack、cloud storage 等）× 4 victim model × 2 defense（细节留待正文），在已存在的 red-team log 上分别应用 oracle 与 3-panel judge。

与现有工作的突破点：三条独立立场。（i）不是新 benchmark——与 AgentDojo / DECOMPBENCH / SafeArena 等 benchmark 论文不同，本文是方法学 tool，可套用于任何已存在的 red-team 结果，采纳成本极低。（ii）oracle × judge 双引擎——deterministic oracle 提供 ground truth 参考；3-panel judge 提供 scalable 部署方式；α = 0.91 表明 judge panel基本可信，但作者诚实报告 共享盲点（escalation chain 系统性未识别）。（iii）三维正交轴——reversibility × cross-scope × privilege 是三条可组合的独立维度，与 7-06 SafetyRepro（configuration 正交）· 7-07 SovereignPA-Bench（八轴价值观）· 今日 agent safety（三机制解耦） 共同构成 H2 "benchmark 拆解派" 家族的第九联。

H2 benchmark 方法学谱系扩展：前八联 物品（IRT）· 搜索（BOA）· 评委（Grader-Repro）· 构造（TASTE）· 配置（SafetyRepro）· 价值观（SovereignPA-Bench）· 多语言（PolyWorkBench）· 经济学（今日 harness · Harness Effect · token/cost）。本文正式开辟第九联：严重度分级联——把聚合二值指标拆解为多级有序尺度。

Action-Graded Severity Scale · L0-L6 七级有序尺度
等级典型场景（示意）ReversibilityCross-ScopePrivilege
L0纯 read-only · 无 scope 变化Fully reversibleNoNo
L1User-scope 可逆 minor write（e.g. draft）ReversibleNoNo
L2User-scope 不可逆 write（e.g. delete own file）IrreversibleNoNo
L3User-visible reversible harm · 跨用户资源可逆ReversibleSame scope, visibleNo
L4Cross-scope 可逆 leak（e.g. temp share）ReversibleYesNo
L5Cross-scope 不可逆 leak · 或 privilege expansion 同 scopeIrreversibleYesPossibly
L6Irreversible cross-scope privilege escalation（最严重）IrreversibleYesYes

注：以上等级说明基于摘要与方法学描述归纳，具体阈值以论文正文为准。三维正交 —— 每一级都是三维组合下的特定 profile，因此 L4 vs L5 差异是"不可逆 + 是否跨 scope"，L5 vs L6 差异是"是否 privilege expansion"。

三条"二值指标看不见"的失败案例

1. Case A · Zero-ASR Cross-Scope Leak：一个 defense 报告 attack-success rate = 0——表面看完美防御。但通过 action-graded severity 追踪：agent 通过未过滤工具把敏感信息 leak 到 externally visible cross-scope（L4-L5）。ASR 二值把这个案例判为"成功防御"，L0-L6 尺度把它判为 L5 cross-scope leak。

2. Case B · 相同 ASR 严重度分布迥异：两个 victim × defense 组合报告的 ASR 相同（比如都是 15%），但一个的失败集中在 L1-L2（低危 · 可逆），另一个集中在 L5-L6（高危 · 不可逆跨 scope）——二值指标把二者视作等价，但对 defender 是天壤之别。

3. Case C · Escalation Chain：多步 tool-call chain 中每一步单看都是 L0-L1（低危），但组合起来产生 L5-L6 危害。这是 3-panel judge 与 oracle 共同的盲点——作者诚实报告：judge panel 系统性未能识别 escalation chain。这是后续研究方向的自然 follow-up。

Deterministic Oracle × 3-Panel LLM Judge 双引擎评估
引擎输入输出特点
Deterministic Oracle完整 tool-call trajectory + attacker stated goalL0-L6Ground-truth 参考 · 需要标注 attacker 目标
3-Panel LLM JudgeTag-free trajectory（无 attacker 目标）· 3 frontier models 面板L0-L6可扩展部署 · Krippendorff's α = 0.91 与 oracle 有序一致

Krippendorff's α = 0.91 —— 有序一致性指标，α ≥ 0.8 通常被视作可靠、α ≥ 0.9 视作高度可靠；本文的 0.91 意味着 3-panel judge 在大部分等级判定 上与 oracle 高度一致。关键盲点：escalation chain 系统性未识别——是未来 judge 改进的自然目标。

对研究方向的启发
对 Benchmark

H2 benchmark 方法学第九联：严重度分级联 / 拆解聚合派——把聚合二值指标拆解为多级有序尺度；九联完整闭合：物品（IRT）· 搜索（BOA）· 评委（Grader-Repro）· 构造（TASTE）· 配置（SafetyRepro）· 价值观（SovereignPA-Bench）· 多语言（PolyWorkBench）· 经济学（今日 harness · Harness Effect）· 严重度（本文）。方法学可复用：(1) 三维正交轴设计（reversibility × cross-scope × privilege）——直接可用于设计其他领域 severity scale；(2) deterministic oracle × 3-panel judge 双引擎——是benchmark 打分方法学的下一代模板，可迁移到 HarmBench / TrustLLM / AIR-Bench；(3) trace-grounded 应用于已存在 log——采纳成本极低，社区可快速复用；(4) 诚实报告 judge 盲点（escalation chain）—— 树立"honest limitation reporting" 学术范式。

对 Agent Safety

与今日 agent safety 报告（2607.07097 Operational Reframing）形成 H2 "拆解派双子星"——两篇同一天提交、共享"拆解聚合数字"哲学：agent-safety 侧拆 pipeline effect 为三机制（reframing · planner · delegation），benchmark 侧拆 ASR 为 L0-L6 七级。二者组合形成agent safety 拆解方法学的完整版。工程侧启发：(1) 部署 red-teaming 时应同时报告 ASR + severity 分布——只报告一个数字会误导决策；(2) escalation chain 是新研究方向——需要专门的 chain-level detector；(3) cross-scope leak 是 7-06 AgentLens 可解释派与7-07 Cedar 形式化派 都应重点关注的场景类型——AgentLens hidden state 检测 + Cedar 硬约束 + 本文 severity 评估 = 三层组合防线。

对 Harness Engineering

本文对 harness 工程有三条深刻启发：（1）harness 内应内嵌 severity-aware 决策——高 severity 潜在动作（L4-L6）应触发 escalation to human；这可直接落到 7-02 Loop Engineering 五级 Verification Ladder 的autonomous-zone 触发条件；（2）trace-grounded 分析 与 今日 harness 报告（Harness Effect）的observability 机制家族天然配合——harness 记录完整 trace，本文尺度直接分析；（3）failure-spend governance × severity governance 组合——今日 harness 说"失败时熔断降 token"，本文说"高 severity 时熔断降风险"，二者本质都是动态预算控制——可统一在同一个 orchestration governance 框架下。
