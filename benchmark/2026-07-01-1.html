摘要（中文翻译，忠实原文）

尽管机器人操作能力快速进步，物理安全仍是部署家用机器人的重大障碍：如果机器人损坏自身或周围环境，任务成功不够。仿真提供了对成本高昂且危险的真实世界训练和评测的无伤害替代方案，然而现有仿真器缺乏通用机制来检测、量化、表示 伤害。为填补这一空白，我们提出 OopsieVerse，一个用于damage-aware 家用操作的统一仿真框架与 benchmark。OopsieVerse 把伤害作为显式的、物理接地的、任务无关信号，将接触力、温度变化、液体交互 等来源转换为对应的机械、热或流体 伤害。OopsieVerse 包含两个核心组件：(1) DAMAGESIM，一个 simulator-agnostic 框架用于导航和操作中的伤害检测与量化；(2) 一组家用任务，评估常见伤害模式，并区分任务完成与安全执行。我们通过在两种物理后端（Nvidia Omniverse 的 OmniGibson · MuJoCo 的 RoboCasa）中实例化 DAMAGESIM 展示了框架的通用性。我们进一步通过多种 use case 展示 OopsieVerse 的价值：(1) 通过实时 damage 反馈引导更安全的 demonstration 收集；(2) 通过 damage-conditioned imitation learning 和 reinforcement learning 学习更安全的 manipulation policy；(3) 对最前沿 VLA policy 的安全性做 benchmark；(4) 改善 sim-to-real 迁移策略在真实世界的安全性。这些结果共同凸显 OopsieVerse 作为可扩展、系统化研究安全机器人操作的开源基础 的潜力。

核心内容解读（问题诊断 / DAMAGESIM 三大 damage 家族 / 双物理后端设计 / 4 use case / 与 VLA safety 谱系的关系）

问题诊断：家用机器人 physical safety 的空白。作者指出机器人操作研究长期把成功率 作为主要指标，而忽略了：机器人可能完成任务但同时损坏自身或周围物体。这个空白在家用场景尤其严重 —— 家里有易碎品（陶瓷、玻璃）· 热源（灶台、烤箱）· 液体（水杯、油罐）· 电器（插座、电线），每个都是 physical safety 的独立维度。当前仿真器（Isaac Sim / MuJoCo / PyBullet）都能模拟碰撞，但没有把碰撞后果作为独立 signal —— 结果 policy 学到"任务完成" 但不学"安全完成"。

DAMAGESIM 的三大 Damage 家族。这是全文核心技术贡献。DAMAGESIM 把散落的物理量统一映射 到伤害轴：

Damage 家族物理源物理量转换典型家用场景
Mechanical（机械）contact forces接触力 / 冲量 / 应力 → 结构变形或断裂陶瓷杯撞台面、木门重击
Thermal（热）temperature changes温度 / 温度梯度 / 曝露时间 → 灼伤 / 熔化 / 燃烧触碰灶台、抓热锅、放塑料到烤箱
Fluid（流体）liquid interactions液体接触 / 浸没 / 溢出面积 → 短路 / 腐蚀 / 变形水杯打翻到电器、油溢出

三大家族的关键设计：物理接地（每个 damage 值都对应真实物理量）+ 任务无关（不与任何具体任务成功率耦合）+ simulator-agnostic（同一个 damage 定义可以在不同物理引擎上实现）。这个抽象层是 OopsieVerse 与既往 "硬编码 collision penalty" 方法的本质区别。

双物理后端实例化。论文在两个物理后端上实例化 DAMAGESIM，证明 simulator-agnostic 属性：

  • OmniGibson（Nvidia Omniverse）—— 高保真渲染 + PhysX 物理引擎 · 适合 RGB / RGB-D 视觉输入的 VLA policy 评测
  • RoboCasa（MuJoCo）—— 快速物理仿真 · 15 个 tasks · 适合 RL 训练与快速迭代（RoboCasa 是 MuJoCo 生态里家用机器人任务集）

两个后端都能承载相同的 damage 定义 —— 只是底层物理量的来源不同。这个设计避免了benchmark 与单一 simulator 绑定 的常见困境。

任务套件设计：显式分离 task completion 与 safe execution。OopsieVerse 家用任务不使用"成功 / 失败" 二元指标，而是每个任务都同时 报告：

  1. Task completion：任务目标是否达成（拿到杯子？完成炒菜？）
  2. Safe execution：过程中 damage 累积量（机械 / 热 / 流体 三条独立轴）

结果四象限：(a) safe success（理想）· (b) unsafe success（完成任务但造成损坏）· (c) safe failure（没完成任务但没伤害）· (d) unsafe failure（既没完成又造成损坏 · 最差）。这四象限与 6-26 ForesightSafety-VLA 的SSR / USR / SFR / UFR 直接同构，两者可以联合报告。

4 大 Use Case 完整覆盖。论文并不满足于只做 benchmark —— 而是展示同一个 damage 信号可以驱动agent 全生命周期：

Use Case ① · Demonstration 收集：真实机器人 demo 收集非常昂贵，且 human demonstrator 可能在不知不觉中制造不安全 demo。DAMAGESIM 在虚拟环境中实时反馈：demonstrator 用 VR 控制机器人时，可视化"你刚才这次抓杯子已产生 3.2 单位机械 damage"，引导 demonstrator 生成更安全的 demo。

Use Case ② · Damage-Conditioned Policy 学习：把 damage 信号条件化 到 policy 训练：imitation learning 中把 damage 作为 filter（拒绝高 damage 的 demo），或作为额外 conditioning input；RL 中把 negative damage 作为 auxiliary reward 甚至 constraint（如 CMDP）。

Use Case ③ · VLA baseline benchmark：对前沿 VLA policy（如 OpenVLA / OpenVLA-oft / RDT / π₀ 等）做系统性 physical safety benchmark。这与 6-26 ForesightSafety-VLA 直接互补：ForesightSafety-VLA 给分类法，OopsieVerse 给底层 damage 量化。可以想象一个"ForesightSafety-VLA × OopsieVerse 组合基准"覆盖13 类失效 × 3 damage 家族 = 完整的物理 safety 评测矩阵。

Use Case ④ · Sim-to-Real Safety Transfer：仿真中学到的 damage-aware policy 迁移到真实机器人时能否保持安全性？这是 sim-to-real 领域一个长期空白 —— 之前的 sim-to-real 只关注能力迁移（成功率），OopsieVerse 首次把safety 迁移 作为独立指标。

与 VLA safety 谱系的位置。OopsieVerse 在 H1 末 - H2 首的具身智能 physical safety 评测 主线上占据一个特定位置：

时间 / 论文层级核心贡献

两者互补：ForesightSafety-VLA 说"要看哪些维度"，OopsieVerse 说"怎么在每个维度上量化"。组合起来构成 H2 具身智能 safety 评测的完整栈。这与 6-30 OSWorld 2.0（数字世界 computer-use safety）形成"物理 × 数字" 安全评测双谱系。

方法学意义。OopsieVerse 也让我们看到 safety benchmark 建设的一个通用范式：不要在任务成功率上做修补，而是引入独立的、物理接地的、任务无关的 safety 信号。这个范式可以推广到 non-physical safety 场景：例如 web-agent 场景下，把"不可逆操作数量 / 副作用范围 / 数据泄露量" 作为独立信号（类比 mechanical / thermal / fluid）。

  • 核心论点 ①：家用机器人 physical safety 不能作为任务成功率的副产品，必须作为独立可量化维度。
  • 核心论点 ②：DAMAGESIM 提供物理接地 / 任务无关 / simulator-agnostic 的 damage 抽象层 —— 三属性缺一不可。
  • 核心论点 ③：safety 信号可以驱动agent 全生命周期—— demonstration / 训练 / 评测 / 部署四阶段。
  • 三大 damage 家族：Mechanical（接触力）· Thermal（温度变化）· Fluid（液体交互）—— 每个都对应真实物理量。
  • 双物理后端：OmniGibson (Nvidia Omniverse) · RoboCasa (MuJoCo) —— 15 tasks in RoboCasa · 证明 simulator-agnostic。
  • 四象限分解：safe success / unsafe success / safe failure / unsafe failure —— 显式区分 task completion 与 safe execution。
  • Use Case ①：demonstration 收集 · 实时 damage 反馈引导 human demonstrator 生成更安全 demo。
  • Use Case ②：damage-conditioned imitation / RL · damage 作为 filter / conditioning input / auxiliary reward / CMDP constraint。
  • Use Case ③：现代前沿 VLA policy 的系统性 physical safety benchmark · 与 6-26 ForesightSafety-VLA 互补。
  • Use Case ④：sim-to-real safety 迁移 · 首次把 safety 迁移作为独立指标（之前 sim-to-real 只关注能力迁移）。
  • 方法学范式：不要在任务成功率上做修补，而是引入独立的、物理接地的、任务无关的 safety 信号—— 可推广到非物理场景。
  • H2 首日双谱系：OopsieVerse（物理世界）+ OSWorld 2.0（数字世界）+ ForesightSafety-VLA（诊断维度）构成完整具身智能 safety 评测栈。
对你三个研究方向的启发
Harness Engineering

(1) DAMAGESIM 的抽象层设计思路可迁移到 KV-cache harness —— 你毕设可以借鉴：定义 KV-cache "物理接地 · 任务无关 · engine-agnostic" 的伤害轴，例如"无效 prefill token 数"、"被驱逐但下轮又需要的 slot 数"、"hit-miss 熵" —— 这些是 SGLang 内部结构量，任务无关，可跨不同 workload 通用；(2) simulator-agnostic 属性 直接对应你毕设的engine-agnostic 目标 —— 同一套 KV-cache 治理策略在 SGLang / vLLM / TRT-LLM 上都应能实现，就像 DAMAGESIM 在 OmniGibson / RoboCasa 上都能实现；(3) 四象限分解：fast success（快且对）· slow success（对但慢）· fast failure（错且快）· slow failure（错且慢） —— 用来重新审视 harness 的评估指标，避免只看吞吐率不看错误传播；(4) 4 use case 全生命周期：你的 harness 也应该覆盖训练时（KV-cache aware 训练）+ 部署时（在线策略）+ 评测时（可复现 benchmark）+ 上下游联动（与推理 backend 集成）；(5) 与 6-30 CUGA FLO 的 7 hook 原语组合：hook 是 harness 内的控制原语，DAMAGESIM 抽象层是度量原语—— 两者组合成"可测量 × 可控制" 的完整 harness 治理栈；(6) 物理接地信号 → 网络接地信号 —— 在 KV-cache 场景，物理接地对应硬件资源接地（HBM bandwidth / GPU utilization / KV memory footprint），你可以定义"资源伤害" 作为独立信号，与 latency / throughput 并列。

Agent Skills Safety

(1) DAMAGESIM 的抽象层思路直接迁移到 skill safety —— 定义"skill 伤害"轴：不可逆操作数（对应 mechanical）· 权限升级数（对应 thermal）· 数据泄露量（对应 fluid）—— 每个都是 skill 执行过程的独立可量化副作用；(2) 与 6-30 Action Alignment "C/R/B 三坐标" + 6-27 Epistemic Property "teachability" + 本文"damage 三家族" 组合成 skill safety 的多层度量矩阵；(3) 四象限对应 skill 执行：safe task-completion / unsafe task-completion / safe task-failure / unsafe task-failure —— 特别是unsafe task-completion（"agent 完成了任务但制造了副作用"）在当前 skill safety benchmark 中长期被低估；(4) damage-conditioned skill 训练：把 damage 信号加入 skill 学习作为 auxiliary reward 或 CMDP constraint —— 直接对应 6-28 RUBAS 的"rubric-based reward"，但把 rubric 从专家标注 4 维 提升到物理接地 3 家族 damage；(5) skill 生命周期 4 use case：对应 6-25 SkillSafetyBench 缺失的部分 —— demonstration 收集时的 skill 使用示范 · 训练时的 damage-conditioned SFT · 评测时的 physical benchmark · 部署时的 sim-to-real skill 迁移；(6) 与 6-30 Action Alignment 的parameter-burden gradient 组合：Action Alignment 说"最省力路径 = 最大权限路径"，本文说"最省力路径也可能 = 最多 damage 路径" —— 两者共同暴露 skill selection 的结构性偏差。

Safety Benchmark（核心方向）

直接为 safety benchmark 建设提供范式级参考：(1) 可通用的三属性 damage 抽象（物理接地 · 任务无关 · engine-agnostic）是任何领域 safety benchmark 的普适设计原则 —— 后续 benchmark 应问自己"我的 safety 信号是否具备这三个属性？"；(2) simulator-agnostic 双后端实例化 应成为 benchmark 建设的基本要求，避免"benchmark 结果绑定单一实现" 的循环论证；(3) 4 use case 覆盖全生命周期 是判断 benchmark 完整性的标准 —— 不要停留在 "只评测 policy"，而是把 benchmark 变成数据 → 训练 → 评测 → 部署 的基础设施；(4) 四象限分解（safe success / unsafe success / safe failure / unsafe failure）是 6-26 ForesightSafety-VLASSR/USR/SFR/UFR 的一致设计 —— 这个分解正在成为 safety benchmark 的de facto 标准，未来的 safety benchmark 都应报告这四象限；(5) 与 6-30 OSWorld 2.0（数字世界 long-horizon safety audit）+ 6-26 ForesightSafety-VLA（VLA 诊断分类法）三者构成具身智能 safety 评测三联拍 —— 覆盖"物理伤害 × 分类法 × 长程数字工作流" 三个维度；(6) 物理伤害范式可迁移到非物理场景：web agent 的"操作副作用"、finance agent 的"信息不对称伤害"、legal agent 的"误建议损失" —— 都可以套用"独立信号 / 任务无关 / 平台无关"三属性框架；(7) 与 7-01 Epistemic Property 的联动：teachability 层测量"agent 是否可教"，OopsieVerse 层测量"agent 是否伤害环境"—— 两者构成 H2 safety benchmark 的认知 × 物理双维度。
