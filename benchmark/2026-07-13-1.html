摘要翻译（忠实原文）

视觉语言模型 (VLMs) 正越来越多被用作安全关键物理系统中具身智能的感知-推理骨干——感知或推理错误可能导致不安全的决策或动作。虽然已经开发出许多 red-teaming 方法来探测 VLM 的漏洞，但它们的评估在数据集、指标、威胁模型 三个维度上均碎片化，使得直接比较困难，并遮蔽了观察到的差异是源于更强的攻击、更脆弱的模型、还是不兼容的评估设置。现有以 chatbot 为中心的 red-teaming benchmark 主要标准化了 jailbreak 与内容安全评估，但它们没有系统性地捕获物理接地的功能失败，也没有覆盖针对物理世界 VLM 的 red-teaming 方法。这提出了核心挑战：如何在统一协议 下比较多样的攻击方法，同时目标于相同的场景特化失败。

我们引入 REALM，据我们所知首个统一红队 benchmark for physical-world VLMs。REALM 在实用黑盒威胁模型 下集成 12 个 red-teaming 方法、3 个 model-agnostic defense、13 个 VLM，共享数据集与指标。为在攻击家族之间对齐对抗目标，REALM 引入 agentic target-generation pipeline，为每个场景构造共享的、场景特化的、物理接地的 攻击目标，从而在对齐的对抗目标下公平比较多样 red-teaming 方法。

评估结论四条：(1) text 与 typographic injection 攻击引发最多失败；(2) multimodal co-optimization 在视觉扰动迁移上最强；(3) single-pass 攻击以远低成本接近 iterative 方法的效果；(4) model scale alone 并不保证对抗鲁棒性。代码开源于 github.com/UCF-ML-Research/REALM。

核心内容解读（约 560 字）

问题背景：2026 H2 具身智能进入 VLM 骨干的时代——从 6-25 ForesightSafety-VLA 到 6-30 OopsieVerse 再到今日 REALM，物理世界 VLM 的部署已从"研究话题" 变为"工业级部署"。但红队方法（red-teaming）呈碎片化：不同论文用不同 dataset、不同 metric、不同 threat model，导致任意两条 red-teaming 方法几乎无法直接比较——A 论文的攻击强 20% 到底是攻击更强、模型更弱、还是评估设置不同？这是 red-teaming 生态的根本性 replicability 危机。REALM 的存在意义：给红队方法一个统一称重台。

核心方法：三层设计。(1) 共享黑盒威胁模型——所有攻击方法只能通过 API 与 VLM 交互，不假设内部 gradient 可用。(2) 12 × 3 × 13 三向网格——12 个 red-teaming 方法（含 jailbreak / typographic / patch attack / co-optimization 等家族）× 3 个 model-agnostic 防御（不依赖特定 VLM 权重）× 13 个 VLM（含 open 与 closed weights）。(3) Agentic target-generation pipeline——这是最关键创新：不同攻击家族在各自 objective 上比较是没意义的（jailbreak 攻击 "让模型说出禁忌词" ≠ perturbation 攻击 "让模型识别错误"），REALM 用一个 agentic pipeline 为每个物理场景生成共享的、场景特化的、物理接地的 攻击目标（例如"让 VLM 在识别红灯 STOP 标志时输出 GO"），所有攻击方法针对同一目标，从而目标对齐 —— 这才是"直接可比" 的严格意义。

四大一手结论（论文里应用于所有 12×3×13 网格）：(1) Text + typographic injection 攻击是最强单类——把恶意文字/字符直接叠到图片上，几乎所有 VLM 都难以抵抗（尤其是能读印刷体的多模态模型）；(2) Multimodal co-optimization 视觉扰动迁移最强——联合优化文本与视觉扰动的攻击，在跨 VLM 迁移 时最稳；(3) Single-pass 攻击接近 iterative 方法的效果，但成本远低——这是防御方非常坏的消息：攻击者不需要迭代很多轮就能达到近似最优，防御窗口极短；(4) Model scale alone 不保证鲁棒性——不能靠"把模型做更大" 来解决，需要专项防御方法。H2 benchmark 谱系再拓展一格：第十一联 · 统一红队协议联 (Unified Red-Team Protocol League)——十联（物品/搜索/评委/构造/配置/价值观/多语言/文化/严重度/预测）+ 本文第十一联。H2 benchmark 家族新范式：从"新增一个 benchmark" 转向"统一现有 benchmark 生态的协议"，是生态位卡死 的高价值工作。

四条一手结论 · 攻击 / 防御的部署意涵
#结论对防御方的意涵
1Text + typographic injection 最强物理世界 VLM 部署必须先做文字/字符 OCR-aware 防御——路牌、警告标签、招牌都可能被投毒
2Multimodal co-optimization 迁移最强不能只测单个 VLM——一旦有一个 VLM 被攻破，攻击很可能迁移到其他 VLM · 部署方需跨模型评估
3Single-pass ≈ iterative 但成本远低防御窗口极短 · 不能寄希望于"攻击者要迭代很多次才能成功"—— 需要第一次触发即拦截
4Model scale 不保证鲁棒性盲目 scale-up 不能解决对抗鲁棒问题 · 必须专项做 adversarial training / input filtering / consistency check —— 7B 与 70B 面临同样风险

物理世界 VLM 部署清单（基于以上结论综合）：先做 OCR-aware 文字/字符防御 → 跨模型评估攻击迁移 → 首次触发即拦截而不是多次拦截 → 不迷信 model size —— 四条实操建议直接可落地。

对研究方向的启发
对 Benchmark

H2 benchmark 谱系再拓展一格 · 第十一联：统一红队协议联 (Unified Red-Team Protocol League)——十联（物品/搜索/评委/构造/配置/价值观/多语言/文化/严重度/预测）+ 本文第十一联。方法学可复用：(1) agentic target-generation pipeline 是全新范式——用 agent 生成场景特化对抗目标，让不同攻击方法在目标对齐 下比较（此前是 dataset 对齐 / metric 对齐，从未做过目标对齐）；(2) 12 × 3 × 13 三向网格——比传统 "N 攻击 × M 模型" 二维网格多一维 defense，让防御方法学同步纳入 benchmark；(3) 黑盒威胁模型统一——所有攻击方法必须遵守 API-only 约束，防止"白盒开挂" 造成的假比较；(4) H2 benchmark 家族新范式：从"新增 benchmark" 转向"统一现有 benchmark 生态的协议"—— 这是生态位卡死 的高价值方向。下一步可预测方向：Chinese Physical-World VLM Red-Team Benchmark（把中国路牌、招牌、监管标志等本土化物理场景嵌入 REALM 协议）—— 可预测的高被引复刻方向。

对 Agent Safety

REALM 的四条一手结论直接是物理世界 embodied agent safety 部署清单：(1) OCR-aware 输入过滤 应成为所有 VLM-agent harness 的默认前置模块；(2) 跨模型迁移评估 应成为 agent safety audit 的标准环节——不能只在部署的那个 VLM 上做 audit；(3) 首次触发即拦截——防御逻辑必须假设攻击是 single-pass，而不是 iterative；(4) 不迷信 model scale——用同一 model family 的 7B 与 70B 面临相同风险，说明 agent safety 是与模型规模正交的独立维度。与今日 agent safety 报告 (Boiling the Frog EU AI Act 44.4% ASR) 形成对偶：Boiling the Frog 是文本+多轮 攻击面下的产业警报，REALM 是视觉+物理 攻击面下的产业警报——两者拼成"两大 modality × 两大时间维度" 的 agent safety 攻击面全景图。

对 Harness Engineering

VLM-based agent harness 需要新增vision-input 层的策略执行——不能只在 tool-call 层做 guardrail。启发：(1) harness 应在 VLM 处理输入图像之前，加一层 image-content policy engine——检测 typographic injection / adversarial patch，与今日 harness 报告 (ActPlane OS 层执行) 拼成"输入内容策略 × 输出动作策略" 双层；(2) harness 层应支持 "跨模型冗余投票"——用多个 VLM 独立评估同一图像，如果结论不一致就报警，防止单点被攻破；(3) harness 层应支持 iterative-attack 检测——如果同一图像在短时间内被多次略微修改后重新输入，应触发告警。H2 harness × REALM 结合：evalci (7-07 统计层) + ActPlane (7-13 OS 执行层) + REALM 输入内容策略层——H2 harness 逐层完整闭合走向工业部署。
