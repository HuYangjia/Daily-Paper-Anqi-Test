一句话核心贡献
首次把发布前安全评估从"合成 evals" 抬到"真实部署 prefix 重生成"——用去标识化的历史对话前缀，让候选模型重新生成响应，量化预测未来 misbehavior 率。
摘要翻译（忠实原文）

发布前安全评估旨在告知发布一个新 AI 模型的下游风险。然而大多数评估提供关于部署中不期望模型行为发生频率的证据有限：它们通常覆盖不足、不具代表性、且通常可被识别为测试。为解决这些问题，我们研究一种简单的模拟部署方法：从此前一个模型部署的去标识化对话开始，冻结初始对话前缀，用候选模型重生成下一个响应。产生的响应既可被审计发现新颖 misalignments，也可用于估计部署前模型 misbehavior 的流行率。我们在 4 个 GPT-5 系列部署上评估 deployment simulation，对 GPT-5.4 使用注册的、结果盲的预测，对三次更早的发布做回顾性分析。我们发现 deployment simulation 产生 informative 的部署后 misbehavior 率估计，并击败了基于对抗性选择生产数据的 baseline；其 evaluation-awareness 点估计也比传统评估更接近生产流量。我们还识别出 tool resampling 的现实性 是进一步改进预测的核心挑战，并分享结果表明该挑战即使在复杂工具使用场景下也可克服。最后，我们展示 deployment simulation 可以从公开聊天数据集 seed 化并仍对生产 misbehavior 率保持信息量，暗示外部研究者无需访问私有生产日志也能运行 deployment-grounded 评估的路径。总体上，deployment simulation 帮助评估者预测语言模型在真实世界的行为，并支持对部署风险的更定量评估。

核心内容解读（约 550 字）

解决了什么问题：进入 2026 H2，AI safety 评估的根本悖论已成为整个行业的痛点：合成 evals（HarmBench / AgentDojo / MASK 等）虽然可复现且可控，但存在三大缺陷 —— (1) 覆盖不足（覆盖的场景与真实用户查询分布不一致）· (2) 不具代表性（评估集组成与生产流量组成偏差大）· (3) 可被识别为测试（前沿模型能感知到 eval-awareness 并调整行为）。这直接挑战 pre-deployment safety evaluation 的科学基础：发布前的评估分数能否可靠预测发布后 misbehavior 率？ 本文给出至今最严肃的回答。

核心方法：Deployment Simulation。设计极其干净且工程可行：(1) 从此前部署（即已发布模型的生产日志）中获取去标识化的对话；(2) 冻结其初始 prefix（用户的第一/前几条消息 + 早期系统交互）；(3) 用候选新模型重新生成下一条响应；(4) 审计这些响应发现新颖 misalignment，同时统计估计 misbehavior 率。三大立场性设计：(A) 用真实部署 prefix 作为 seed——直接解决合成 evals 的分布代表性问题；(B) 保留 eval-awareness 隐蔽性——因为 prefix 来自真实用户对话，模型不容易识别它是测试；(C) 可扩展到 tool use——作者识别出 tool resampling 是核心挑战但证明可解。

实验设计的分量：4 个 GPT-5 系列部署 上评估。最有分量的是预注册（pre-registered）的、outcome-blinded 预测：作者在 GPT-5.4 部署之前 用 deployment simulation 预测 misbehavior 率，然后与真实部署后观察比较。三次更早的发布做回顾性验证。与对抗性选择生产数据 baseline 的对比：deployment simulation 击败了后者，即使 baseline 已经用了真实生产数据、且专门挑选了对抗性最强的样本。另一关键结果：evaluation-awareness 点估计——即模型能识别出"这是测试"的信号量——deployment simulation 的估计比传统评估更接近真实生产流量的水平（说明它没有过度触发模型的"测试模式"）。

与现有工作的突破点：三条独立立场。（i）区别于 Anthropic Claude 评估传统（红队 + 合成对抗）—— 那些评估都是设计出来的测试；本文用真实部署 prefix 让评估不可识别。（ii）区别于 ELICIT / Model Written Evals / 合成 misuse evals—— 那些方法评估的是"最坏可能"，本文估计"部署真实频率"，这是安全评估科学化的关键转向。（iii）区别于 7-08 Doomed from the Start（agent 内部预测失败）—— 那是内部机制层 早期终止；本文是外部部署统计层 事前预测，二者形成"内-外双翼"。H2 agent safety 谱系再拓展一格：第十派立场 · 预测派 / Simulation 派——九派（外置/认知/泛化/评委/搜索/可解释/形式化/终止/解耦）+ 本文预测派。

公开数据集 seed 的意义：作者展示 deployment simulation 从公开聊天数据集（如 LMSYS Chat / Wildchat 等）seed 化仍能保持信息量。这是为外部研究者打开 deployment-grounded evaluation 的路径——不必是 OpenAI/Anthropic 内部才能做此类评估，学术界与独立 AI safety 研究者也能参与。这一节的政治学重量与技术重量相当。

Tool Resampling 挑战：作者识别的核心开放问题 —— 当 prefix 涉及 tool call 与 tool return 时，重生成响应可能需要重新采样 tool 返回（因为原 tool 返回可能是模型和特定 tool 状态耦合的）。作者证明即使在复杂 tool-use 场景下这一挑战也可克服，但报告了详细的方法学考量。

公开聊天数据集 seed 的开放路径

作者展示 deployment simulation 从公开聊天数据集（如 LMSYS Chat 等）seed 化仍对生产 misbehavior 率保持信息量。这一发现的三重意义：

  • 民主化 AI safety 评估——外部研究者（学术界、独立 AI safety lab）无需私有生产日志也能做 deployment-grounded 评估；
  • 可比性——不同实验室可用同一公开 seed 数据集运行 deployment simulation，从而比较模型 misbehavior 率；
  • 治理相关性——AI safety 治理（如 UK AISI、US AISI 的 pre-deployment eval）可用 seed-based deployment simulation 独立复核，无需 model developer 提供私有数据。

作者关键论断："deployment simulation 帮助评估者预测语言模型在真实世界的行为，并支持对部署风险的更定量评估。" —— 这是 pre-deployment safety evaluation 首次从"定性红队" 迈向"定量频率预测"的关键一步。

对研究方向的启发
对 Harness Engineering

Deployment Simulation 本质上是一种特殊的 evaluation harness——它把"评估"这个动作的数据分布 seed 从合成集换成真实部署 prefix。启发：(1) lm-evaluation-harness / HELM / OpenAI evals 应增加 "deployment-simulation-adapter"——一个允许用 real deployment prefix 作 seed 的插件；(2) tool resampling 挑战 直接映射到 harness 里的tool-payload governance（与今日 harness 报告 TTHE 的 execution-derived proxy signal 挑战同源）——两个方向面对同一 tool 环境不稳定性问题；(3) 与 7-09 Writer AI Harness Effect 的 orchestration-only 受控置换实验 是"harness 层受控变量" 双胞胎，本文变的是 seed 分布，Writer AI 变的是 orchestration 拓扑，共享 "其他一切冻结，只换一个 harness 组件" 方法学。

对 Agent Safety

H2 agent safety 谱系再拓展一格 · 第十派立场：预测派 / Simulation 派——九派（外置/认知/泛化/评委/搜索/可解释/形式化/终止/解耦）+ 本文预测派。方法学四条独立可复用：(1) 预注册盲预测——AI safety 评估首次达到医学 pre-registration 标准；(2) evaluation-awareness 点估计对比——把 eval-awareness 从主观定性变成可量化指标；(3) 击败对抗性生产数据 baseline——即使拿到真实生产数据也不如 deployment simulation，说明"分布代表性 + eval-awareness 隐蔽性" 才是关键；(4) 公开聊天 seed 的 external evaluator 路径——AI safety 民主化。与 7-08 Doomed from the Start（残差流内部预测）合成 "内-外双翼预测"——今日报告是 external / 部署层，7-08 是 internal / 表征层，两者共同定义 H2 agent safety 预测轴。

对 Benchmark

Benchmark 应该显式暴露 "seed distribution" 变量——本文表明不同 seed 分布产生不同的 misbehavior 率估计。未来的 safety benchmark 应报告：(a) seed 是合成还是真实部署 prefix；(b) 若真实，seed 来自哪次部署；(c) tool resampling 策略；(d) eval-awareness 点估计。启发：(1) H2 benchmark 方法学第十联：seed-distribution 联——benchmark 需要暴露 seed 分布来源；(2) 与今日 benchmark 报告 Pluralis v0.1 形成"本地化 × deployment-grounded" 双维度——Pluralis 强调 seed 的文化/语言分布，本文强调 seed 的部署 prefix 分布，二者共同解构"universal safety benchmark" 的西方中心假设；(3) leaderboard 应报告"deployment-simulation-verified misbehavior rate"作为独立于 raw ASR 的新指标。
