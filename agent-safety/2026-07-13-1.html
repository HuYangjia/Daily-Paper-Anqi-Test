一句话核心贡献
把 agent safety 评估从单轮 refusal 推进到 渐进多轮 stateful workspace 攻击——工件状态成为 unsafe 判定对象，EU AI Act 首次落地 benchmark。
摘要翻译（忠实原文）

背景：语言模型的传统安全 benchmark 评估生成文本——模型是否输出有害语言、是否复制偏见、是否遵从有害指令。当模型作为 agent 部署时，安全相关对象从"系统说了什么"转移到"系统在环境中做了什么"，仅评估 prompted response 已不足以 应对 AI 提出的安全挑战。近期出现了作为 agent 评估 LLM 的 benchmark，本文延续这一脉。

方法：我们引入 Boiling the Frog，评估在公司与办公室场景部署的工具使用 AI 模型是否易受渐进式攻击。每个场景以 benign workspace edits 开始，后续引入一个 risk-bearing 请求。benchmark 聚焦 stateful multi-turn 评估：chain 暴露一个持久 workspace，把 risk-bearing payload 放在轮次序列的可控位置，评分依据是由此产生的 artifact state 是否变得不安全。场景通过三层operational risk taxonomy 组织，扎根于 Boiling the Frog risks、AI Act Annex I 与 Annex III 高风险语境、以及 EU AI Act 通用人工智能 (GPAI) 行为准则 (Code of Practice)。

结果：跨 9 模型 panel，aggregate strict attack success rate (ASR) 为 44.4%。模型级 ASR 范围从 Claude Haiku 4.5 的 20.5% 到 Gemini 3.1 Flash Lite 的 92.9%；Seed 2.0 Lite 也在 80% 以上。Chain 类别平均 ASR 在 Code of Practice 失控 (loss-of-control) 场景达到 93.3%。

核心内容解读（约 560 字）

问题背景：2026 H2 agent safety 评估已经完成七派立场（外置 / 认知 / 泛化 / 评委 / 搜索 / 可解释 / 形式化）× 三派新增（终止 / 解耦 / 预测），但绝大多数 benchmark 仍停留在单轮 尺度——给一个有害提问，看 agent 是否拒绝。真实企业部署完全不是这样：agent 在持久 workspace（文件、表格、code repo、DB 事务）中工作，攻击者可以先做一堆完全合法的编辑让 agent 建立"这是良性工作流" 的上下文信任，然后再 引入一个 risk-bearing 请求——即"温水煮青蛙"。这类攻击与 6-06 DECOMPBENCH 的分解攻击 相似但更进一步：Boiling the Frog 追踪的是artifact state 累积，而非仅仅评估单个 subtask 的 refusal。

核心方法：三层设计。(1) Stateful multi-turn chain——每个场景是一个连续对话序列，暴露一个持久 workspace（文件系统 / 电子表格 / repo）；risk-bearing payload 放在 chain 的可控位置（第 3 轮 / 第 5 轮 / 第 7 轮），研究其对 attack success 的影响。(2) Artifact-state 判定——不看 agent 是否口头拒绝，而是看最终 workspace 中的工件（提交的代码 / 保存的表格 / 发送的邮件）是否安全。这是 agent safety 评估对象的本体性升级：从 utterance 到 artifact。(3) 三级风险分类学——第一层"Boiling the Frog risks"（温水煮青蛙特有风险，如上下文诱导、工件重定向、边界侵蚀）；第二层扎根 EU AI Act Annex I（禁止性 AI 实践）+ Annex III（高风险 AI 系统）；第三层扎根 EU GPAI Code of Practice（尤其"失控 loss-of-control" 类别）。这是首个把 EU 立法体系直接嵌入 benchmark 结构的工作。

关键实验发现：9 模型 panel · aggregate strict ASR 44.4%。四大发现：(1) 模型分层极其陡峭：Claude Haiku 4.5 20.5% ↔ Gemini 3.1 Flash Lite 92.9%（4.5 倍）—— safety 训练细节比参数规模影响大得多；(2) Seed 2.0 Lite > 80% —— 字节 Seed 系列在渐进攻击下明显脆弱，这是首次公开报告 该系列的 multi-turn agentic 表现；(3) Code of Practice 失控场景 chain-level ASR 93.3% —— 几乎无一模型能守住"失控" 类别，说明 EU 立法关切与实际 agent 弱点严重不匹配；(4) benign→risk 位置越靠后 ASR 越高（论文中可查）—— 温水煮青蛙效应实证。H2 agent safety 第十一派：立法接地派 (Regulation-Grounded Evaluation)——十派立场（外置/认知/泛化/评委/搜索/可解释/形式化/终止/解耦/预测）+ 本文第十一派立法接地派。是第一个把 EU AI Act 从 policy paper 变成可执行 benchmark 的工作。

对研究方向的启发
对 Agent Safety

H2 agent safety 谱系再拓展一格 · 第十一派：立法接地派 (Regulation-Grounded Evaluation)——十派立场（外置/认知/泛化/评委/搜索/可解释/形式化/终止/解耦/预测）+ 本文第十一派。方法学可复用：(1) artifact-state 而非 utterance 作为 safety 判定对象——所有企业部署 agent 都在 stateful workspace 中工作，评估必须跟着改；(2) benign→risk payload 位置化控制——把"哪一轮插入 risk request" 作为可控变量，量化温水煮青蛙效应；(3) 立法 taxonomy 嵌入 benchmark——从 EU AI Act / GPAI CoP 直接映射类别，让 benchmark 结果具有合规审计价值；(4) 44.4% aggregate strict ASR 是产业级警报：现有 Claude/Gemini/Seed 系列前沿模型近半场景在渐进攻击下失守，安全训练需要在multi-turn stateful 场景专项加强。与今日 harness 报告 (ActPlane OS 层执行) 形成对偶：Boiling the Frog 从攻击面 证明 tool-call 层不够、必须监控 artifact state；ActPlane 从防御面 给出 OS 层执行方案——两者拼成"艾滋病要往哪里查 · 抗生素往哪里下"。

对 Harness Engineering

harness 必须承担artifact-state 追踪 的一等公民责任 —— 不能只挂 tool-call hook。启发：(1) harness 需要把 workspace 全生命周期状态作为可查询对象，任何 write / commit / send 都要在 policy engine 视野内（对齐今日 ActPlane OS 层拦截思路）；(2) chain-level "位置分布" 应成为 harness 的可观测指标—— agent 在 conversation 第 N 轮做的 write，比在第 1 轮的同样 write 风险大得多，harness 需要跟踪 "risk-accumulate score"；(3) 立法关切 mapping 应嵌入 harness 报告—— 每次 harness 部署的 audit log 里应含"本部署可能触发 EU AI Act Annex III XX 类" 提示。与 7-08 Yi/Song Harness MDP + 7-10 TTHE 组"训练时 × 测试时" 的 harness 层，本文提供合规时 (compliance-time) 一维——harness 三时协同。

对 Benchmark

Benchmark 方法学再拓一联 · 第十二联：立法接地联 (Regulation-Grounding)——十一联（物品/搜索/评委/构造/配置/价值观/多语言/文化/严重度/预测/文化）+ 本文第十二联。方法学可复用：(1) taxonomy 三层化（本 benchmark 原创 + 立法条款 + 行业行为准则）；(2) 状态级评分——benchmark 的 unsafe judgment 直接查 artifact state 而非 llm-as-judge；(3) chain-level 与 payload-position 二维报告——是 DECOMPBENCH 单向分解 与 Boiling the Frog 状态化 差异的关键。H2 benchmark 家族级议题：下一步做Chinese CS-3.5 立法 × Boiling the Frog 复刻（中国生成式 AI 服务管理办法 + 深度合成规定 + AI 安全治理框架 → benchmark taxonomy Layer 2/3）——是可预测的高被引方向。
