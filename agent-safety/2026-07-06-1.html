摘要（中文翻译，忠实原文）

基于大语言模型（LLM）的编码 agent 展现出显著的自主能力，但在与外部环境的多轮交互 中也带来了显著的安全与滥用风险。现有的安全机制主要依赖外部 guardrail，其在执行时 进行细粒度行为控制的能力有限。同时，近期用于 LLM 安全的机制可解释性 方法大多局限于单轮或 jailbreak 类 QA 场景，难以刻画多轮 agent 执行中演化的风险动力学。本文从内部视角 研究多轮编码 agent 的安全问题，提出 AgentLens（Mechanistic Subspace Intervention and Steering），一个针对编码 agent 的white-box 防御框架——在运行时进行安全检测 与表征层缓解。与常规 agent guardrail 不同，AgentLens 从step-level hidden representation 检测有害执行状态，并通过在单层 内介入 10 维子空间 来抑制不安全行为。为支持该研究，作者引入 Mechanistic Agent Safety (MAS) benchmark：包含 194 tasks 的完整标注多轮执行轨迹，覆盖 LLaMA-3.1-8B · Qwen-2.5-7B · Gemma-2-9B 三个模型。大量实验显示：AgentLens 取得强安全检测性能，为 look-ahead 风险预判 提供了初步证据，并大幅减少编码 agent 的有害行为，为把机制可解释性应用于动态 LLM agent 安全 奠定了基础。代码开源于 github.com/EddyLuo1232/AgentLens。

核心内容解读（问题 / MSIS 机制 / MAS benchmark / 三大结果 / 派系定位）

问题背景。2026 上半年 agent safety 的六派立场（外置派 · 认知派 · 泛化派 · 评委派 · 搜索派 · 可解释派）都在指出同一件事：agent 的安全约束不是单点问题——不是"拒绝一个 harmful prompt" 就能解决的。已有方案有两类结构性缺陷：(1) 外部 guardrail（SafeHarbor / RUBAS / AgentDoG 等）—— 在 agent 外面套一圈，看到的是输入输出黑箱，无法在执行中途 精细阻断；(2) 机制可解释性研究（representation engineering / activation steering / RepE）——大部分只在单轮 QA / jailbreak 场景验证，从未在多轮 agent 全轨迹 试过。AgentLens 是把二者桥接 起来的第一次尝试：把 mechanistic interpretability 的 white-box 干预下沉到多轮 agent 的 step level，从内部看 agent 的每一步。

MSIS：10 维 subspace × 单层 steering。本文核心机制 Mechanistic Subspace Intervention and Steering 有三个关键设计选择：

设计选择为什么这样做结构性含义
只干预10 维 subspace大量证据显示 harmful concept 在 hidden state 里往往是低秩 的（RepE / Anthropic Golden Gate Claude 都是几维到十几维）最小侵入性 · 保留模型通用能力 · 避免"手术式副作用"
只干预单个 layerSparse Autoencoder / activation steering 研究表明 middle layer 是 safety-relevant concept 最集中的位置推理开销近乎零 · 可以在 production forward 里做 in-place hook
从step-level hidden representation 检测Multi-turn agent 的风险经常是累积的、跨步的——单看某一步 output 看不出能识别"此刻虽然合规但正朝不安全轨迹演进" 的前瞻风险

这三条一起把 MSIS 定位成"agent 内部的实时安全传感器 + 微干预"——像为 agent 装了一个心电监护 + 起搏器：既能测出何时"心律不齐"（有害表征上升），也能在同一层直接干预（10 维推力矫正）。

MAS Benchmark：机制可解释性研究的第一份 agent safety 数据集。作者不仅提方法，还配了专为 mechanistic interpretability × agent safety 设计的 benchmark。三大关键特性：(1) 194 tasks · 覆盖典型多轮编码 agent 场景——包括文件系统操作、外部 API 调用、代码执行、长期任务；(2) 完整标注多轮执行轨迹——每一 step 的hidden representation + action + 有害标注，供社区做 SAE / RepE / probe / steering 研究；(3) 三家模型全覆盖——LLaMA-3.1-8B（Meta）· Qwen-2.5-7B（阿里）· Gemma-2-9B（Google）——保证跨模型可迁移性。MAS 是 H2 mechanistic interpretability × agent safety 基础设施空缺的一次填补。

三大实验结果。论文报告了三条核心结论：(a) 强安全检测——用 step-level hidden representation 做二分类可以达到高准确率地识别 harmful state（论文正文报告具体 AUC）；(b) look-ahead risk anticipation——初步证据显示 hidden representation 能预判后续步骤的风险，不是被动检测；(c) 大幅降低 harmful actions——在 194 tasks 上执行 subspace steering 后有害行为显著减少，同时保留任务完成能力（safety-utility 权衡改善）。这里最有影响力的是 (b)——如果确凿，说明agent 的"意图"在 representation 里比在 action 里更早显形——这是 white-box early warning 的可能性根基。

H2 派系定位：第六派 · 可解释派 / white-box 派。把本文放回你追踪的 H2 agent safety 派系谱中：

  • 外置派（6-30 Action Alignment）——refusal 是 category error，safety = action alignment，需要外置约束
  • 认知派（7-01 Epistemic Property）——safety 是 epistemic property，behavioral snapshot 不够
  • 泛化派（7-02 Why Generalize）——H_∞ 分析证明 safety 不会随任务泛化
  • 评委派（7-03 Necessary but Not Sufficient）——LLM-as-Judge grader 本身不可靠
  • 搜索派（7-03 BOA）——safety measurement 是搜索问题不是抽样问题
  • 可解释派 / white-box 派（本文 · 2026-06-21）——safety 应该看得见 · 说得出 · 控得住，从 hidden representation 层面干预

前五派主要是立场 / 测量 / 理论 —— 说明"safety 应该怎么想"；本文是第一派 可运行时部署 的方法学——说明"safety 应该怎么做"。这是 H2 上半月立场谱系闭合后第一次向工程侧回落。

Harness Engineering

(1) Harness 的新拓扑：Interpretability-aware harness——AgentLens 显示 harness 不必是"外面套一层"，也可以是"在 forward 里挖一个 hook"；harness 层可以直接调用 model 内部 representation；(2) 与你 SGLang KV-cache 毕设的直接联动：mechanistic steering 需要在 forward 时修改 hidden state，这与 KV-cache reuse 存在直接冲突——如果 cache 缓存了未经 steering 的 hidden state，那么下游 KV-cache 命中会绕过 safety intervention；毕设可以做"steering-aware KV-cache invalidation policy"：安全干预层的 hidden state 必须不 cache 或 重新计算；(3) 与 7-03 Grader-Repro 的KV-cache 精度是 non-determinism 来源 呼应：如果 subspace steering 用 int8 hidden state 会不会失效？—— 需要在 harness 层报告 quantization tier × steering 有效性 的联合表；(4) MAS benchmark 是harness reference implementation ——你可以把 SGLang 集成为 MAS 的后端选项，让 3 backbone 都可以用 SGLang 加速跑 MAS，从而实证"KV-cache aware harness 对 MAS 结果有无影响"，形成硕士毕设 harness-level 的一条完整实验；(5) 与 7-02 Loop Engineering 组合：loop specification 的 verification 组件 可以引入 subspace-steering signal 作为一等 verifier —— "如果 harmful subspace projection > threshold，则终止循环"；(6) 这是mechanistic-interpretability-based harness 的开山之作——你可以在毕设中提出"KV-cache-mechanistic co-design" 概念：cache 决策与 mechanistic hook 联合优化。
