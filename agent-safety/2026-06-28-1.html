摘要（中文翻译，忠实原文）

LLM 演化为工具使能 agent 带来了一类新的安全挑战——它们与真实世界执行 相关，而不仅仅是文本生成。已有的对齐方法常常依赖粗粒度的拒绝信号或静态监督，使得在多样的 agentic 风险下平衡"安全" 与"有用工具执行" 变得很难。

我们提出 RUBAS，一个基于 rubric 的强化学习 框架，用于 agent 安全。RUBAS 把 agent 行为分解为四个维度：tool-use safety（工具调用安全）、argument safety（参数安全）、response safety（响应安全）、helpfulness（有用性）。这些结构化 rubric 在完整的 agent 轨迹上提供细粒度、可解释 的奖励，让强化学习能同时 优化安全的工具使用和任务完成。在多个 agent 安全基准与多个模型上的大量实验显示：RUBAS相对标准对齐基线显著提升安全，减少了工具基的幻觉，并保持竞争力的 utility。我们的结果表明：多维 rubric 奖励是在 safety-critical 的工具使用场景下对齐 LLM agent 的有效训练信号。

核心内容解读（4 维 rubric 设计 / GRPO 端到端 / safety-utility Pareto 打破）

动机：refuse 二值在 agent 时代直接失效。过去 6 个月 agent safety 文献链条逐渐暴露一个事实：对话时代有效的"refuse-only" 训练信号在 agent 时代直接坏掉——agent 调用工具时，拒绝 与正确执行 之间存在多维 的安全光谱（该不该调用、参数是否泄密、最终响应是否暴露、是否过度拒绝伤害 utility）。SFT / DPO 的粗粒度对齐信号要么过度拒绝（BFCL 从 83.7 跌到 60.7），要么训练崩塌（GLM-4.7-Flash 上 Rule / GuardModel / DPO 三种方法 BFCL 直接归零）。RUBAS 给出的答案是：把训练信号结构化分解。

4 维 rubric 设计：把 agent 行为切成 4 个正交维度。

维度判定内容scorer 类型
Tool-Use Safety是否仅在适当时调用工具 / 避开受限工具 / 遵守逻辑顺序程序化确定性
Argument Safety是否避免敏感/私密/越权参数 / 参数落在安全范围程序化确定性
Response Safety最终响应是否禁止禁止信息 / 保持 utilityQwen3Guard-Gen-8B（仅此一项 LLM-judge）
Helpfulness仅对良性合规请求，任务完成度与服务质量程序化确定性

每维 score $r_i = \text{norm}(\sum_j \alpha_{ij} c_{ij} / \sum_j \alpha_{ij}) \in [-1, 1]$，$c_{ij} \in \{0,1\}$。总奖励 $R_{\text{rubric}} = \sum_i w_i r_i / \sum_i w_i$。权重按数据类型固定：Harmful（tool=3, arg=0.5, resp=2.5, help=0）/ Sensitive（2.5/2/1.5/2.5）/ Benign（0.5/0.5/0.5/3）。最终奖励含 completion 与 reasoning 惩罚：$R = R_{\text{rubric}} + R_r$ 若 $R_c=1$，否则 $-0.5$。关键设计：除 refusal-judgment 外，所有 scorer 是程序化确定性检查——这避开了 LLM-judge 的reward hacking（6-25 Hacker-Fixer Loop 警告的核心问题）。

GRPO 端到端在线优化。RL 算法选 GRPO（Shao 2024 / DeepSeekMath）—— 同一 prompt 采样 $n=8$，组内归一化优势，比 PPO 更省 critic、比 DPO 更适合多轮 trajectory。训练超参：学习率 $8\times 10^{-6}$、BF16 全参数、batch 32、max turns 4、3 epochs。训练集 2,353 条（Harmful 2,000 + Sensitive 235 + Benign 118）。所有模型跑 thinking mode—— 这是 H1 末新成为标配的设置。

对你三个研究方向的启发
Harness Engineering

RUBAS 对 harness 工程链条的启发是"把 harness 的成功标准也 rubric 化"：(1) 4 维 rubric 思路可直接平移 KV-cache harness——cache 命中率（hit）/ 计算正确性（correctness）/ 内存峰值（memory-safe）/ 延迟达标（latency-helpful） 四维评分，避免单一 throughput 指标掩盖隐性故障；(2) 程序化确定性 scorer—— KV-cache 的每一维都可以做成确定性检查（cache 是否一致、numerical 是否对齐、显存是否超 SLA），避免依赖 LLM-judge；(3) GRPO 端到端优化—— 当 KV-cache 配置变得 cross-cutting 时（spec decoding + paged attention + radix tree），可以用 GRPO 把"下一步该改哪个组件" 直接当 multi-arm bandit 优化；(4) 权重按 workload 类型固定（Harmful/Sensitive/Benign 不同权重）对偶 KV-cache 的 workload-aware 权重（prefill-heavy / decode-heavy / multi-tenant 不同权重）；(5) 与 6-26 NOVA 的 architecture gradient 形成姊妹方法—— NOVA 提供"下一步改什么" 的离散信号，RUBAS 提供"当前状态打多少分" 的连续信号，二者叠加 = 完整 harness 演化反馈环。

Agent Skills Safety（直击方向）

这篇是 H1 末"训练信号怎么造" 一拍的代表作，与 6-26 AgentDoG 1.5（数据净化）共构姊妹方法：(1) 4 维 rubric 设计 可直接被 skill safety 复用——把 SkillSafetyBench 的 6 风险域 × 30 类别折叠成 tool/arg/response/help 四轴，让 skill-mediated 攻击的训练信号有结构；(2) 程序化确定性 scorer——这是 skill 安全可复现的关键，"是否调用了不该调的 skill" 是确定性可测的；(3) workload-aware 权重—— Harmful/Sensitive/Benign 权重不同，skill 场景应再加一档 Skill-Compromised（skill 本身被污染但用户无恶意），权重应学 Sensitive 而非 Harmful；(4) GRPO 在 thinking mode—— 让 agent 在 reasoning 中显式给出 4 维 rubric 自评，再用 KL 约束训练；(5) 不二选一—— RUBAS 证明 safety + utility + tool-honesty 可以三同向，未来 skill safety 研究应放弃"refusal-rate 是 safety 主指标" 的误区；(6) 开源缺失—— RUBAS 没释出代码（只引 AReaL/TRL 训练框架），这是其评分不到 95 的核心扣分项，本方向后续工作需要补足。

Safety Benchmark

RUBAS 对 safety benchmark 设计的间接启发：(1) 多维 rubric 评分 应该同时 成为 benchmark 报告口径—— 当前 benchmark 报 ASR / refusal-rate 但很少同时报 utility / tool-honesty，导致"训练得越安全越笨" 这种 trade-off 被掩盖；(2) 程序化 scorer 应该是 benchmark 必备—— LLM-judge 是过去两年 benchmark gaming 的元凶，今日 #3 REALM 已经显示 PromptInject 在 LLM-judge 下虚高；(3) workload type 权重—— Safety benchmark 应该区分 Harmful / Sensitive / Benign 三种 split 分别报数字，而不是把它们混在一个 ASR 里；(4) 跨 backbone 稳健性—— Safety benchmark 应该至少在 dense + MoE 双 backbone 上报告，否则一个方法的 MoE-崩塌 漏洞会被掩盖；(5) 训练数据规模小（2,353）是 benchmark 设计的 reminder—— Safety 训练集不应该堆量，而应该堆结构化 rubric 标注；(6) 与今日 #3 REALM 的agentic target-generation pipeline 形成"训练侧 rubric 化 × 测试侧场景化" 完整闭环。
