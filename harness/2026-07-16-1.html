摘要翻译（忠实原文）

串行验证门（serial verification gates）是 LLM harness 中的核心可靠性原语：候选答案只有在 k 次验证器调用全部接受 时才返回。在条件独立 门的假设下，最近的 Odds Law（arXiv:2606.15712）证明后验 log-odds 关于 k 线性增长——因此失败率指数衰减——并明确指出："a tight theory of partially correlated verifier cascades remains open"（部分相关验证器级联的紧凑理论仍未解决）。本文给出这样一个极简理论：把每实例的 false-accept rate 建模为潜变量 α ∼ G（de Finetti 交换性），精确的级联后验为 ℓ_k = ℓ_0 − ln m_k，其中 m_k 是 G 的第 k 阶矩。由此得到四条结论：(i) ℓ_k 关于 k 凹（对任意非退化 G）——Odds Law 只是第一门的切线兼上界；(ii) 对 Beta(a,b) 潜变量，失败率多项式衰减 1−r_k ≍ k⁻ᵇ，相关参数 ρ_v = 1/(a+b+1)；(iii) 在 α=1 处的 blind-spot 原子（mass 1−π）把可从任何数量的 gate 中提取的 evidence 上限锁死在 −ln(1−π) nats——可靠性饱和于 1 以下；(iv) 让 true-accept rate 也变化（β ∼ H），得到三分法：gates 最终 always help / plateau / actively harm，由 G、H 上尾指数决定，closed-form 交叉点 k†。机制是幸存者偏差：能穿过 gate 的错误是高 α 那些。理论可测量：每实例 R 次重复裁决可识别 G 的前 R 阶矩，2 次即可估计 ρ_v；beta-binomial 似然 + NPMLE 可恢复完整可靠性曲线与 ill-posed ceiling。合成实验中：独立性外推在 k=5 低估失败率 20 倍、k=10 低估 ~3000 倍；R=8 的相关拟合可跟踪 held-out 深度。实用杠杆是去相关——换模型家族、换模态、换证据源——而非加 gate。

核心内容解读（约 620 字）

问题背景：LLM harness 里最常见的 verifier 组合方式是"多把 gate 串起来 AND"——只要 k 把验证器全通过就发布答案。这是过去两年 self-consistency · verifier ensemble · guarded ReAct · MCP tool-checks 等一切"可靠性增强"技巧的共同数学骨架。2026-06 的 Odds Law 论文证明：在条件独立 假设下，log-odds 随 k 线性增长，因此失败率指数衰减——工程界据此形成"多加 gate 就能把 error 降到 10⁻⁶" 的直觉误区。但同一篇论文明确坦言："部分相关级联的紧凑理论仍未解决"。本文正是回应这一 open problem 的精准补丁——单作者、14 页、纯数学，回敬 harness engineering 一个基础工具。

方法：de Finetti 潜变量框架。作者把 per-instance false-accept rate 建模成潜随机变量 α ∼ G——同一实例的多次验证在 α 给定条件下独立，跨实例的 α 服从分布 G。这是标准的 de Finetti 交换性 建模——数学优雅、可校准。关键结果 ℓ_k = ℓ_0 − ln m_k 的直觉是：每加一门 gate，后验的减法项是"G 的第 k 阶矩的对数"——由 Jensen 不等式立即得出 ℓ_k 关于 k 凹：Odds Law 的线性只是本文凹函数在 k=1 处的切线。选 G = Beta(a,b) 时，m_k 有闭式，导出多项式衰减 k⁻ᵇ——远慢于指数——这解释了工程实践中"gate 越加边际收益越小"的普遍观察。Blind-spot atom：G 在 α=1 处放一点原子质量 1−π（表示"这类错误任何 gate 都识别不出"），则无穷多 gate 也只能给出 −ln(1−π) nats 的 evidence——可靠性天花板不是 1，是 π。让 true-accept β ∼ H 同时变化后，得到三分法：gate 最终 always help / plateau / actively harm，取决于 G、H 的上尾指数比较；closed-form 交叉点 k† 明确指导"何时该停加 gate"。

可测量性 + 实证冲击：理论最漂亮的一点是可用少量重复裁决估计 G——每实例 R 次重复识别 G 的前 R 阶矩，只需 2 次即可估 ρ_v = 1/(a+b+1)；然后 beta-binomial + NPMLE 恢复完整可靠性曲线。合成实验数字触目：独立性假设在 k=5 处低估失败率 20 倍、在 k=10 处低估 3000 倍——工程界过去两年"多加 gate 更可靠"的估算可能全部大幅乐观。作者点出实用杠杆：提升可靠性的正确方向是"去相关"——换模型家族（不同预训练分布）、换模态（视觉 vs 文本）、换证据源（独立数据库）——不是加更多 gate。

H2 harness 谱系新增第十三层：Reliability Theory 层（可靠性理论层）——与 7-15 的 Evaluation Protocol Critique 层（评估协议批判层，Yike Wang / UW+AI2）构成"批判姐妹"：一位在拷问 评估协议 是否成立，一位在拷问 可靠性外推 是否成立——两条批判合成 harness engineering 走向数学化的关键双拍。哲学突破：harness engineering 需要属于自己的统计理论支撑——像 information theory 之于通信、queueing theory 之于分布式系统——本文是这条路上的第一块奠基石。

对研究方向的启发
对 Harness Engineering

H2 harness 谱系再拓展一格 · 第十三层：Reliability Theory 层（可靠性理论层）——七层图 + 经济学层 + Test-Time 演化层 + OS 执行层 + Meta-Optimization 层 + Evaluation Protocol Critique 层 + 本文 Reliability Theory 层。这一层与 7-15 的 Critique 层构成"数学化批判双子星"——一位质疑评估协议，一位质疑可靠性外推。方法学立刻可复用：(1) Beta-Binomial NPMLE 相关性校准——所有 verifier ensemble 论文应报告 ρ_v；(2) Blind-Spot audit——识别 π 值（可识别错误的最大比例）作为 harness 天花板，超过后必须换 evidence source；(3) 三分法 k†——为"停止加 gate" 提供 closed-form 判据，避免过度堆叠；(4) 去相关设计矩阵——把 verifier 库按"模型家族 × 模态 × 证据源" 三轴组织，硬性避免同族 verifier 堆叠。下一步预测：Reliability Theory 层将迅速被 GitHub 上的 harness 项目实现——因为校准协议非常轻量（R=2 就能启动），且能直接反驳"我们加了 5 门 verifier 所以更可靠" 这类营销话术。

对 Agent Safety

本文的"去相关而非加 gate" 教训对 agent safety 有直接迁移价值：(1) safety filter ensemble 的相关性诅咒——如果多个 refusal classifier 都在同一 RLHF 数据上训练，即使加 5 层 filter 也只降低指数上界的 log 项一点点；(2) 与 今日 agent-safety 报告 Operational Reframing (Liu et al., 2607.07097) 呼应——Gemini 在 Claude planner 下从 8.9% 合规率飙到 38.9%，正是"planner-executor 相关性未建模" 的典型体现；(3) Blind-Spot 类比"未知 unknown 攻击面"——任何 safety benchmark 都存在 π < 1 的可探测比例，越 blind 的攻击类别越难被 filter 抓到，加多少 filter 都封不住这个上限；(4) safety verifier 设计建议：与其把 refusal + policy + content-moderation 三个 filter 都用同一 LLM，不如把其中一层换成符号 regex 或第二种 LLM 家族——本文的去相关杠杆直接翻译为 heterogeneous defender ensemble。

对 Benchmark

Agent benchmark 的可靠性外推现在有了数学工具——本文的 Beta-Binomial NPMLE 可以立刻用于 benchmark 层的多裁判一致性 建模：(1) LLM-as-Judge benchmark 的相关性校准——同一 benchmark 用多个 LLM 打分时，本文告诉我们判分相关性会让"多裁判平均" 的方差降低比独立假设慢得多；(2) 与 今日 benchmark 报告 How Many Tasks Are Enough (Huang, 2607.12338) 呼应——Huang 证明部分预算即可支持决策 · 本文提供另一维："部分裁判"（R 次重复）即可估计相关性——两者合成"部分预算 · 部分裁判 · 部分 verifier" 的三维 benchmark 效率科学；(3) benchmark 报告新要求——所有 agent benchmark 应在提交任务后报告 ρ_v 和 π，让读者知道"再加多少裁判" 才能得到显著性；(4) H2 benchmark 方法学第十六联：Correlation-Aware Aggregation 联——从"平均 3 个 LLM 分数当 ground truth" 抬到"用 Beta-Binomial NPMLE 校准相关性再聚合"；这一联将成为 KDD 2027 / NeurIPS 2027 benchmark track 的方法学门槛。
