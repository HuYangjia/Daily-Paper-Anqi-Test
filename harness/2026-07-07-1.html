一句话核心贡献
把 harness 时代最基础但最被忽视 的一步——"A 比 B 强"的统计推断——打包成一个pip 安装、一函数调用、独立参考验证 的 Python 库，把 lm-evaluation-harness / HELM 的 per-item 表转成可发表级别的 CI + 配对显著性 + 多重比较修正 声明；并以 MMLU 9-模型公开比较为例展示：3 / 8 对相邻 leaderboard 排名不显著——直接给当前 leaderboard 文化补上第一个可执行的诚实工具。
摘要（中文翻译，忠实原文）

当前语言模型评估的主流做法是：每个模型报一个 accuracy 数字，谁高谁强——却不检验 差距是否可能只是抽样噪声。在几千个题目的基准、以及模型自我复现差异都可能大于模型间差距的 temperature sampling 下，这种做法常常高估 头条结论的可信度。修正它的统计机制——置信区间、配对显著性检验、power 分析、聚类标准误、多重比较修正——早已成熟，但没有标准 pip 包 把这些以评估实际的数据形态（即 per-item results table）为输入组织起来。我们发布 evalci，一个纯 Python（仅依赖 numpy/scipy/pandas） 的库：把 per-item results 表一函数调用 转换成可发表级别的声明——例如 "Model A beats Model B, Δ=3.1 pts, 95% CI [1.2, 5.0], paired permutation p=0.002, n=1,319"——并配套 lm-evaluation-harness 和 HELM 输出的适配器。每条 routine 都对独立参考 做了验证（statsmodels 或暴力精确枚举），而不是只验证自己。作为案例研究，我们重新分析了 9 个语言模型在 MMLU 上的公开比较——发现 8 对相邻 leaderboard 排名差距中有 3 对在对 36 对隐含 pairwise 比较做 Holm 修正 后并不显著。evalci 已在 PyPI 上发布，源码在 GitHub，DOI 见 Zenodo。

核心内容解读（问题 / 三条缺失 / 库结构 / 独立参考验证范式 / MMLU 案例 / 与 H2 harness 六层图定位）

问题背景。2024–2026 三年的 leaderboard 战争，把"公开 benchmark 上 A 比 B 高多少 pts" 变成了公司宣传语——但社区始终缺一个让每篇论文、每张排行榜、每条 blog 都能一函数调用 加上 CI 和显著性的工具。这不是"没人知道要做"——统计学界早在 1960 年代就有 paired t-test、bootstrap、permutation test、Holm-Bonferroni；机器学习界也有 McNemar、Wilcoxon signed-rank 等经典工具；但它们从未被打包成"per-item results table → publication-ready claim" 的单函数 API。evalci 就是这个缺口的填补——它不发明新方法，而是把成熟方法工程化到 harness 时代的数据形态。

作者点出的三条缺失。这些缺失都是 2026 leaderboard 文化的直接后果：

缺失后果evalci 补法
① 报 accuracy 但不报 CI3.1 pts 的差距 vs 4.5 pts 的 CI 半宽——差距在 CI 内 却被宣传成"显著超越"paired bootstrap / analytic Wilson / normal-approx CI 三选一
② 单跑一次 temperature≠0 就下结论模型自我复现差异 可能大于模型间差距（与 7-03 Grader-Repro 的 690-call 数据完全一致）K-run 分布内 self-vs-self CI + 跨模型 CI 双报
③ Leaderboard 排名 = "N 个 pairwise 比较"，但从不做多重比较修正9 个模型 → 36 对比较 → 单尾 α=0.05 下期望 1.8 个假阳性——却被当作"排名可信"Holm-Bonferroni / Benjamini-Hochberg 内置

evalci 的 API 形态。论文强调"one function call"——目标是让评估作者不用写胶水代码。核心用法（论文摘要 & GitHub README 归纳）：

  • 输入：per-item results table——每一行是 (item_id, model_A_correct, model_B_correct[, subject, cluster_id])——正是 lm-evaluation-harness 和 HELM 的输出形态。
  • 调用：evalci.compare(table, model_a="A", model_b="B", method="paired_permutation", ci="bootstrap", correction="holm")——一次返回Δ、CI、p-value、n、method 用于哪个 assumption、多重比较后是否显著。
  • 输出：Publication-ready 一句话，比如 "Model A beats Model B, Δ=3.1 pts, 95% CI [1.2, 5.0], paired permutation p=0.002, n=1,319"——可以直接粘到论文里。
  • 覆盖：置信区间、配对显著性、power 分析、聚类标准误、多重比较修正 五大类。
  • 适配器：lm-evaluation-harness（EleutherAI · 链接）+ HELM（Stanford CRFM · 链接）输出格式直接吃。

独立参考验证：一次真正严肃的软件工程学。evalci 最加分 的部分不是它的功能，而是它的验证纪律——每条 routine 都对独立参考 做了对比：（a）statsmodels ——公认的 Python 统计标准库，用来对照 permutation test / CI / Holm 修正的结果；（b）brute-force exact enumeration——对小样本情况做穷举所有 permutation，得到数学上精确 的 p-value 作为 ground truth。这个纪律解决了一个 harness 时代的元问题：如果统计工具本身有 bug，那么 harness 层的一切"严谨性" 都是幻觉。这与 7-06 SafetyRepro "先证有限包络命题、再报 pairwise disagreement" 的数学 → 实证 一致范式属于同一哲学：把 harness 的每一层都对齐到数学参考点。

MMLU 9 模型案例研究。作者用 evalci 重新分析了一个公开的 9-模型 MMLU 比较——这是 1,319 items 的经典 benchmark（4 分类 subjects），9 个模型两两比较等于 36 对 pairwise。结论：8 个相邻 leaderboard 排名的 gap 中，3 个在 Holm 多重比较修正后不显著——即"第 N 名 vs 第 N+1 名" 的差距不能拒绝零假设。这句话的含义 是：目前1/3 以上的相邻 ranking 差异 都是抽样噪声——但每一次都被公司/论文/blog 当成"SoTA 超越" 报道。这是一个非常干净的行业惯性打脸——不需要新算法、不需要更多数据、只需要一个诚实的统计工具。

核心数据亮点 / 关键论点
  • 核心论点 ①：Leaderboard 相邻排名差距 应默认假设是抽样噪声，而不是能力真差——除非做过配对显著性 + 多重比较修正。
  • 核心论点 ②：模型自我复现差异（K 次重跑）可能大于模型间差距——与 7-03 Grader-Repro 的实证一致，本文补上"如何用统计包装" 的最后一步。
  • 核心论点 ③：统计工具本身也要有独立参考验证——否则 harness "严谨性" 是幻觉。
  • 关键数据 · 案例规模：MMLU 1,319 items × 9 模型 × 36 对 pairwise——公开数据可复现。
  • 关键数据 · 结论：Holm 修正后 3 / 8 对相邻排名不显著——直接反驳"SoTA 提升是真的" 的默认叙事。
  • 方法学 · 依赖：numpy + scipy + pandas 三件套——无重型 ML 依赖，可以在 CI/CD 中运行。
  • 方法学 · 验证：每条 routine 对 statsmodels 或 brute-force exact 枚举做独立参考——工具-of-工具的最高严谨度。
  • 产品化 · 三生态位：PyPI · GitHub · Zenodo DOI——完整锁定学术引用与工程采用两条路径。
  • API 形态：一函数调用 输出 publication-ready 一句话——workflow 阻力最小化设计。
  • 适配器：lm-evaluation-harness / HELM 两大主流 harness 输出格式即插即用。
  • 覆盖统计工具：CI · 配对显著性 · power 分析 · 聚类标准误 · 多重比较修正 五大类。
  • 拓扑定位：与 ReContext / CUGA FLO / Loop Engineering / Grader-Repro / SafetyRepro 合成 2026 H2 harness 工程六层图——本篇是统计层。

Agent Skills Safety

(1) Agent safety benchmark 的"A 比 B 安全" 判定问题最严重——因为 safety scores 常常是 0/1 二元 harmful-action count，样本量小、方差大；如果不做 CI + 显著性，"defense A vs B 差 2%" 完全可能是抽样噪声——evalci 是 agent safety 社区立刻可用 的诚实工具；(2) 与 7-03 BOA 搜索派的组合：BOA 用搜索 找 unsafe trajectories 而不是 sampling——搜索出来的 harmful count 也需要 CI + 显著性——evalci 直接吃 BOA 的 per-trajectory 输出；(3) 与 7-06 AgentLens 可解释派的组合：AgentLens 的 MAS benchmark（194 tasks × 3 backbone）本身就是 pairwise scenario benchmark——用 evalci 做defense-A vs defense-B 显著性检验，可以量化"steering intervention 到底带来了多少真实安全提升"；(4) Skill-facing attack benchmark 的显著性问题（6-25 SkillSafetyBench）：如果 defense 在 100 个 attack scenarios 上成功率 87% vs 85%——差 2% 的 CI 半宽大概率是 3-4%，Holm 修正后大概率不显著——evalci 会把这些"不真实的提升" 剔除；(5) 更深层的启发：H2 agent safety 七派立场（外置 / 认知 / 泛化 / 评委 / 搜索 / 可解释 / 形式化派 —— 见今日 agent-safety 报告）之间的defense comparison 也应该用 evalci——否则"形式化派 vs 认知派 差 3%" 之类的比较毫无意义；(6) 立即可创建的产品：evalci-agentsafety extension——把 attack success rate / defense refusal rate / task completion under attack 三类 metric 直接吃进去，输出 defense pair 的 publication-ready 显著性声明。

Safety Benchmark

(1) Safety benchmark 更需要统计严谨——因为 safety failure 是低频事件（1% level 或更低），样本量对显著性极其敏感；evalci 提供的power 分析 直接告诉 benchmark 作者："如果你想在 α=0.05 检出 Δ=0.5% 的 safety 差异，你至少需要 n=8,000 items"——这是当前几乎所有 safety benchmark（HarmBench / TrustLLM / AIR-Bench / MAS）都违反 的 rule；(2) 与 7-02 IRT-Safety 的深度组合：IRT 精选 informative subset 减少 items × evalci 报显著性——两者合成"信息论选题 + 频率论显著" 的完整 benchmark 严谨性栈；(3) 与 7-06 SafetyRepro 的组合：SafetyRepro 报 pairwise reversal rate（配置扰动下） × evalci 报单一配置下的 CI + 显著性——两层正交，SafetyRepro 说"换配置就翻"，evalci 说"就算不换配置也未必显著"——两者组合刀刀见血；(4) 立即可创建的新 benchmark：Benchmark-Reliability-Score (BRS)——把 4 个维度打包成单一分数：K-run stability（评委层）· configuration flip rate（配置层）· pairwise significance rate（统计层）· power at Δ=1%（统计层）——所有主流 benchmark 都可以报一个 BRS，让作者/公司无处躲藏；(5) MMLU 案例可复用：作者已经复现了 MMLU 9 模型 36 对比较——社区可以立刻把这个例子扩展到 HarmBench / SafetyBench / AIR-Bench——H2 应该有一系列 "evalci-audit-of-X" 帖子，比如"3/8 相邻 leaderboard 排名在 HarmBench 上不显著"；(6) 长期看，这是心理测量派（IRT）+ 频率派（evalci）+ 数学派（SafetyRepro） 三派的融合——2026 H2 benchmark 方法学六联拍正式闭合（物品 IRT / 搜索 BOA / 评委 Grader-Repro / 构造 TASTE / 配置 SafetyRepro / 统计 evalci）。
