一句话核心贡献
把 LLM agent 的 harness 从"固定基础设施"抬到"可学习控制层"—— Harness MDP + advantage-weighted regression + 冻结 LLM 执行器。
摘要翻译（忠实原文）

LLM agent 通常通过修改 prompt、模型或手写工作流来改进，而围绕模型的执行 harness 被视作固定基础设施。我们主张 harness 本身就是一个可学习的控制层。 我们把 harness 运行形式化为一个有限视界的 Harness MDP：一个轻量控制器选择结构化执行动作，而 LLM 执行器保持冻结。控制器用只有终端任务-rubric 奖励的离线 rollout，通过 advantage-weighted regression 训练。我们还把最终任务质量与一个 post-hoc 的 Harness Maturity Score 分离——后者衡量 harness 是否遵循可靠的执行模式，而不只是最终答案是否正确。这一分离带来了 harness 学习的有限缓冲区视角：最终质量增益需要 offline buffer 中的高回报支持，而过程行为只要与 advantage-weighted actions 对齐就能发生迁移。在六个受控域和两个公开 benchmark 适配器 上，学习到的控制器一致改进了验证行为，并选择性地改进最终任务质量，最大增益出现在 adapted τ-bench retail、adapted AgentBench DB-Bench 和使用校准结构验证器的 coding。相对 behavior cloning 和 Forced CHECK 的消融表明，增益既不能被"模仿"、也不能被"简单加检查"解释。这些结果表明harness 控制是冻结 LLM agent 的一个可学习层，同时也说明 offline support 会限制何时"更好的过程控制"能真正翻译成"更好的最终答案"。

核心内容解读（500 字）

解决了什么问题：Claude Code / Codex / lm-evaluation-harness 时代，社区讨论 harness engineering（6-30 CUGA FLO · 7-02 Loop Engineering · 7-06 ReContext）时都手工设计固定执行结构——本文首次把这个假设推翻：harness 结构本身可以学。它不是模型、也不是 prompt，而是一层独立于 LLM 参数的控制层。

核心方法：三件套。（1）Harness MDP 形式化：状态 = 轨迹进度 + draft 状态 + rubric 覆盖率 + 错误计数 + 剩余预算 + 上一动作；动作 = observe · retrieve · call-tool · draft · check · revise · submit 七个（共享跨域接口，无效动作由域适配器 mask）；奖励 = 只有终端 rubric 得分。（2）Advantage-Weighted Regression (AW)：从 base + exploratory rollouts 中收集 offline buffer，用 exp(A/β) 加权最大化 log π_θ(a|s)；控制器仅为一个 64 隐藏单元的单层 MLP，Adam lr=10⁻³，β=0.2，权重裁剪 [0.1, 10.0]，batch 256，20 epochs，3 seeds。（3）Harness Maturity Score (HMS)：7 个过程事件的归一化加权（CheckBeforeSubmit、EvidenceBeforeClaim、TestBeforeSubmit、RevisionAfterFailure、ValidToolUse、StopWhenSufficient、−EarlySubmit），仅用于评估、不作训练奖励。

与现有工作的突破点：三条独立立场。（i）区别于 6-30 CUGA FLO（手工 policy）· 7-02 Loop Engineering（手工 loop spec）· 7-06 ReContext（training-free 推理时管理）——本文提供 harness 工程第七层：学习派。（ii）区别于 6-25 Interplay-Harness、7-04 HASE 这类联合演化模型权重 的方法——本文冻结 LLM，只训练 harness 控制器，工程侧最省资源、也最容易叠加到现有 harness。（iii）区别于 forced-structure 干预方式（在每步强制插入 CHECK）——AW 是状态依赖控制，能学会"什么时候该 check、什么时候该跳"，在 5/8 设置同时打败 BC 和 FC 两条基线。

H2 首月 harness 谱系闭合更新：七层图形成——context（7-06 ReContext）· 策略（6-30 CUGA FLO）· 循环（7-02 Loop Engineering）· 评委（7-03 Grader-Repro）· 配置（7-06 SafetyRepro）· 统计（7-07 evalci）· 学习派（本文）——本篇为最后一层、也是最"结构性"的一层：把整个 harness 变成可优化对象。

实验结果亮点

1. 三大公开设置的最终质量提升（相对 base harness）：

设置Base GAW GΔ (95% CI)CheckBeforeSubmit
τ-bench retail (adapted)0.3370.519+18.2 pp [+15.1, +21.3]17.2%
AgentBench DB-Bench (adapted)0.4150.547+13.2 pp [+10.2, +16.2]16.7%
Coding (calibrated verifier)0.7120.812+10.0 pp [+5.9, +14.6]17.8%

2. 过程行为跃迁：Base 中 1080 episodes 只出现 1 次 CheckBeforeSubmit → AW 中 1080 episodes 出现 113 次（113 倍跃迁）；6 域中 5 域 HMS 提升（research 因 EarlySubmit 从 0% → 25% 抵消收益）。

3. 消融击败两条 baseline：AW 在全部 8 个设置都优于 behavior cloning；在 5/8 设置同时优于 BC 和 Forced CHECK（forced-insert 检查）——说明增益既不是模仿、也不是机械加检查，而是状态依赖控制。coding 上 BC lift = −8.3 pp，AW lift = +10.0 pp，ΔΔ_{AW−BC} 高达 +18.3 pp。

4. 有限缓冲区理论：作者证明最终质量增益上界 σ_B = G*_B − Ḡ_B（buffer slack），只有当 offline buffer 存在高回报支持时才能达成——这解释了为什么 6 个受控域中"过程改善普遍、最终增益局部化"在 3 个高回报支持的设置上（coding · τ-bench retail · DB-Bench）。

对研究方向的启发
对 Harness Engineering

H2 harness 工程七层图完整闭合：context（7-06 ReContext）· 策略（6-30 CUGA FLO）· 循环（7-02 Loop Engineering）· 评委（7-03 Grader-Repro）· 配置（7-06 SafetyRepro）· 统计（7-07 evalci）· 学习派（本文）。学习派是元层——把前六层的手工设计升级为可优化对象。本篇 + 同作者姊妹篇 (2607.04528 belief divergence) 共同奠定 Yi/Song 学派：harness 是可测量、可学习、可优化的中间对象。工程可复用点：（1）七结构化动作 API 可以直接叠加到 lm-evaluation-harness / OpenAI evals 的执行层；（2）AW 用 offline buffer 训 64 unit MLP，工程成本极低，可作为"免费加装的执行策略优化器"；（3）HMS 分离过程质量与最终质量，直接对应 harness 报告新指标。

对 Agent Safety

Harness MDP 视角给 agent safety 提供新的干预点——不改模型、不改 prompt、只改执行结构就能显著提升 CheckBeforeSubmit / EvidenceBeforeClaim 等 safety-relevant 过程行为。这与 6-30 Action Alignment（外置派）· 7-06 AgentLens（可解释派）· 7-07 Cedar Policy（形式化派） 形成第八条正交路径："harness 学习派 safety"——把 safety 作为 rubric 的一部分放入终端奖励，用 AW 训练一个"safety-aware harness controller"，即可运行时部署且不动模型参数。同时对 7-07 Cedar 形式化派的补充：Cedar 提供 硬约束，本文 AW 提供 软性状态依赖偏好，二者叠加是自然工程路线。

对 Benchmark

本文对 benchmark 方法学有两条深刻启发：（1）"benchmark 分数是 harness 依赖的"——同一个 LLM 在同一个 τ-bench 上换 harness 就能 +18.2 pp，与 7-06 SafetyRepro（configuration 单变量翻转 pairwise 结论） 形成互证。leaderboard 应显式标注 harness 配置，否则数字不可比。（2）"过程质量与最终质量应分离报告"——HMS 是可迁移到任何 agent benchmark 的正交维度。H2 benchmark 方法学七联拍初步显现：物品（IRT）· 搜索（BOA）· 评委（Grader-Repro）· 构造（TASTE）· 配置（SafetyRepro）· 价值观（SovereignPA-Bench）· 过程（HMS/本文）——本文可视为 benchmark 方法学的第七联开端。
