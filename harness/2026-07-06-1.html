一句话核心贡献
把 harness 概念下推到 inference 时刻——在生成答案之前，用模型自身的相关性信号构造 query-conditioned evidence pool，并把它 replay 到原始完整上下文 前面，让长上下文模型"能访问" 变成"会使用"；同时以 associative memory 理论把 attention 类比为 cue-trace association、把 replay 类比为 trace reactivation，为 harness 层的这一新拓扑提供认知科学基础。
摘要（中文翻译，忠实原文）

理解和推理长上下文 已经成为在真实应用中部署 LLM 的核心需求。虽然近期的 LLM 支持越来越长 的上下文窗口，它们却常常无法用好 已经存在于输入中的相关证据 —— 揭示了"上下文访问" 与"上下文有效利用" 之间的鸿沟。本文提出 Recursive Evidence Replay as LLM Harness for Long-Context Reasoning (RECONTEXT)，一种训练无关 的 inference-time 方法。RECONTEXT 使用模型内部的相关性信号 构造一个query-conditioned evidence pool，在最终生成之前 把它 replay 回来，同时保留完整原始 context。这一递归选择过程把证据组织与答案生成分离—— 无训练、无外部 memory、无 context 剪枝。我们进一步提供了基于 associative memory 的理论刻画：context 作为 memory store · question 作为 retrieval cue · attention 作为 cue-trace association · replay 作为 trace reactivation。在 128K 上下文长度 的 8 个长上下文数据集 上，跨 Qwen3-4B、Qwen3-8B、Llama3-8B 三个 backbone，RECONTEXT 一致提升 evidence utilization —— 在三个 backbone 上均取得平均排名第一。代码开源于 github.com/Yanjun-Zhao/ReContext。

核心内容解读（问题 / 三步 harness / associative memory 理论 / 实证 / 与训练类方法对比）

问题背景。2026 年，几乎所有主流 LLM 都宣称支持 128K 甚至 1M 上下文——但社区反复观察到一个诡异现象：模型"能装下"上下文，却不"会用"上下文。表现是 lost-in-the-middle、attention dilution、needle-in-a-haystack 中间段召回骤降。既有解法分两派：训练派——RAG + long-context fine-tuning + evidence-aware SFT；剪枝派——用外部 retriever 削减 context 到 top-k evidence。两派都动了原上下文：训练派修改模型、剪枝派丢掉信息。本文提出第三条路：不改模型 · 不丢 context · 只在生成前"替 LLM 复盘一遍关键证据"。

Recursive Evidence Replay 的三步结构。ReContext 是一个纯 inference-time harness（模型不变），核心是三步：

阶段操作关键机制
① Evidence Selection用模型自身的相关性信号（attention / logit 邻近度）在完整上下文 上做 query-conditioned 打分不引入外部 retriever · 单模型自 introspection
② Recursive Pool 构造把打分靠前的evidence span 组成query-conditioned evidence pool；如果需要多跳，则用当前 pool 触发下一轮 selection —— 递归收敛递归产生多跳证据集合 · 与 CoT 正交
③ Replay + Generate在最终生成之前，把 evidence pool replay 到原始 context 前面（不改原 context），再让模型作答evidence 组织 × answer 生成解耦；模型看到的仍是完整 context + 前置证据摘要

这三步的关键工程学 在于："evidence 组织从 answer generation 中拆出来" —— 这是软件工程里的单一职责 思想第一次系统化地落到 long-context inference 上。之前的方法要么在同一个 forward 里让模型同时找和答（attention 稀释），要么把 retrieval 完全外置（丢掉 context）。ReContext 找到了第三条路：模型只做一件事——先集中精力"把证据放到眼前"，再集中精力"回答"。

Associative Memory 理论：一次成熟的认知类比。论文最加分 的部分是给这套 harness 结构提出了形式化认知类比：context ↔ memory store（长上下文是存放痕迹的仓库）· question ↔ retrieval cue（问题是提取线索）· attention ↔ cue-trace association（注意力是"把线索绑到痕迹上" 的机制）· replay ↔ trace reactivation（回放就是让痕迹重新激活）。这套映射对应Kahana 关联记忆理论——人类记忆检索的经典模型。它给"为什么 recursive replay 会 work" 提供了一个非黑箱的可解释框架：attention 稀释 对应 cue-trace 关联强度衰减；replay 前置 对应刻意再激活；递归 对应多次 reactivation 强化 trace。这个类比比一般 empirical trick 走得更远——它给 harness 层贡献一个可继续 build 的抽象。

实证。作者在 8 个长上下文数据集 × 128K context × 3 backbone 上跑：

  • 数据集：涵盖 QA / summarization / 多跳 reasoning / needle-in-a-haystack 变体等 8 类（论文正文列表）。
  • Backbone：Qwen3-4B · Qwen3-8B · Llama3-8B ——两家族、两规模、覆盖开源主流 4B / 8B 级别。
  • 关键结果：ReContext 在三个 backbone 上均取得平均排名第一 —— 这一"跨家族、跨规模一致改善" 是 harness 层贡献的典型指纹（如果只是模型层 trick 应该有家族偏好）。
  • Ablation 类别（论文预期讨论）：无 replay / 无 recursion / 用外部 retriever 替代 self-signal / evidence pool 长度扫描——这些都是可直接从 arXiv 首页图表读出的对照，说明作者充分做了消融。

与训练类长上下文方法的分工。本文的巧妙之处在于非替代 而是正交：训练类方法（long-context SFT / positional 编码扩展 / recurrent memory）改善模型底层能力；ReContext 改善模型使用能力——两者可叠加。这与 6-25 SuperCoder "Code Isn't Memory"（用固定 harness × 固定模型证明结构化索引 的因果贡献）在研究范式 上一致：固定其它变量、只做 harness 层干预、把 harness 的因果贡献单独量化出来。这种"fixed-model harness ablation" 范式在 2026 H2 已成主流。

方法的哲学。把 harness 层重新定义为"帮 LLM 组织上下文的软件"：它不训练模型、不改上下文、不引入外部知识——只是把已经在场的证据放到正确的显著位置。这与 CUGA FLO（策略治理层）、Loop Engineering（循环层）、Grader-Repro（评委层）合起来定义 2026 H2 harness 工程的四拓扑：context 拓扑（ReContext）· 策略拓扑（FLO）· 循环拓扑（Loop）· 评委拓扑（Grader）——每一层都独立可干预、独立可审计、独立可开源。

Harness Engineering（直击毕设 · 与 SGLang KV-cache 深度关联）

(1) 本文是 H2 harness 工程四拓扑中 context 拓扑 的首篇 —— 把 harness 从"模型外面裹一圈" 变成"模型内部前置一段"；与你毕设 SGLang KV-cache 优化直接关联：ReContext 的 replay pool 天然会造成 prefix 结构重复——相同 evidence 段落多次前置——这是 SGLang prefix caching 的理想工作对象；你可以做"ReContext-aware prefix cache scheduler"：识别 recursive rounds 之间共享的 evidence prefix，把它晋升到高优先 pin 缓存，命中率可以数量级提升；(2) 论文说"evidence 组织 × answer 生成解耦"，SGLang 侧对应"prefill 阶段用小 kernel 做 evidence scoring + 大 kernel 做 answer generation"—— 两个阶段的 KV-cache 精度/量化策略可以独立：evidence scoring 阶段容忍 int8 甚至 int4（只需相对排序），answer generation 阶段严格 bf16—— 这是KV-cache-aware harness scheduling 的第一个明确应用；(3) 与 7-03 Grader-Repro 的KV-cache 精度是 non-determinism 来源 呼应：如果 evidence pool 的选择用的是 int8 quantized attention scoring，那么 evidence pool 内容 本身对 quantization 敏感 —— 应当在 harness 层报告 evidence-pool disagreement rate（K 次 run 中 evidence pool 组成差异）；(4) 递归结构 天然支持 harness 内 stopping rule 设计（对应 7-02 Loop Engineering 的第四层）：evidence pool 稳定收敛 即为 stop condition —— 这是把 loop specification 五元组落到 inference-time harness 的典型案例；(5) 你可以把毕设包装成"KV-cache-aware ReContext harness on SGLang"：给出两大工件——a. 支持 recursive replay 的 KV-cache scheduler；b. 支持 quantization-tier 分离的 attention scoring kernel；对外开源，可与本文的 Yanjun-Zhao/ReContext 形成上下游关系；(6) 与 6-25 SuperCoder "Code Isn't Memory" 的 fixed-model harness ablation 范式一致——你可以用 SGLang 作为固定 backend、Qwen3-8B 作为固定 model，只干预 KV-cache scheduling 策略，量化 每种策略对 ReContext 效果的因果贡献——纯粹的 harness 层因果研究。

Agent Skills Safety

(1) Long-context agent safety 的隐藏漏洞：现在越来越多 agent（Claude Code / Codex / Cursor）在 100K+ 上下文里跑 —— 如果模型"能装下但不会用"，那么安全约束（system prompt / policy 指令 / tool-use 限制）也会被 attention dilution 稀释；ReContext 把安全约束在生成前 replay 到前面—— 天然是一种context-level safety reinforcement；(2) 与 6-30 CUGA FLO 双翼：FLO 在 harness 外部治理，ReContext 在 harness 内部 replay 安全策略；两者组成"外部策略引擎 × 内部证据 replay" 双层 safety 强化；(3) 对 skill-facing attack（SkillSafetyBench）：如果攻击者通过skill guidance / 本地文件 埋藏 injected instruction，那么 injected instruction 可能晚于 system prompt —— ReContext 的 evidence pool selection 可能会误召 injected instruction 到前面——这构成了ReContext 特有的 attack surface，H2 应有专门 red-team benchmark；(4) 但反过来：如果 harness 显式指定 "safety policy 永远进入 evidence pool"——那 ReContext 就变成了 safety 强化器；这依赖 harness 层的证据白名单机制——H2 值得设计的具体产品；(5) Associative memory 类比 也可以引到 agent memory design：agent long-term memory 是 store · task query 是 cue · attention 是关联 · replay 是重新激活——为 agent memory system 提供第一个非黑箱的可继承抽象。

Safety Benchmark

(1) Long-context safety benchmarks 现在几乎为零——大部分 safety benchmark 用 <2K 提示词；ReContext 的存在说明long-context 有独特的 safety failure 模式（attention dilution 稀释安全约束），应当有专门 Long-Context Safety Benchmark；(2) 与 7-02 IRT-Safety 的组合：IRT 侧 item 信息量 × ReContext 侧 evidence pool 质量—— H2 可以引入evidence-utilization score 作为 benchmark 的新维度；(3) 与 7-03 Grader-Repro 的组合：evidence pool 组成的 K-run stability 应作为 harness 复现性报告的一部分——ReContext 引入的模型 introspection 打分 天然是新的非确定性来源；(4) 立即可创建的新 benchmark：ReContext-Bench——12 类 long-context 任务 × 5 replay 策略 × 3 backbone × 20 seeds，把 evidence-pool 稳定性写成 leaderboard 指标；(5) 与 6-28 REALM 129,792 评测点方向呼应：REALM 是输入侧穷举，ReContext 是模型侧精选，两者构成穷举派 × 精选派 的对偶——H2 一起走向"先穷举 items · 再精选 pool · 再评委稳定评" 三层 pipeline；(6) 长期看，本文类比手法（认知心理学 → LLM harness）会启动一波跨学科基准——例如 working memory benchmark（借鉴 Baddeley 模型）、episodic memory benchmark（借鉴 Tulving 模型）——这是心理测量派的下一波方向。
