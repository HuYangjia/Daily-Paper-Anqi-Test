一句话核心贡献
通过 6 模型 × 22 任务的受控置换实验，把 agent harness 从"辅助层"抬到"企业级 token 经济学的决定性杠杆"—— cost -41% · wall -44% · tokens -38% · quality 平齐。
摘要翻译（忠实原文）

当今 Agentic AI 开发靠"token maxing" —— 用 token 买能力（更长的推理轨迹、更多轮次、更大的工具载荷、更大的重放上下文），使得每任务的 token 增长速度快于任务价值。单价下降掩盖了这一模式；总花费仍在上升。我们主张：对抗 token maxing 的决定性杠杆是 harness——即组装 context、暴露工具、编排轮次、委派工作、承载企业可观测性与治理的编排层。我们通过受控置换隔离这一层：22 个锁定评估任务、6 个基础模型（Claude Sonnet 4.6、Gemini 3.1、Gemini Flash 3.5、Qwen 3.6、GLM 5.1、Palmyra X6），只改变编排层——冻结的传统生产 loop vs Writer Agent Harness。保持模型不变，harness 把 blended 单任务成本降 41%（0.21→0.12）、中位墙钟时间降 44%（48s→27s）、每任务 token 降 38%（14.2k→8.8k），任务完成质量持平（0.78→0.81，样本量下方向性一致）。效率是模型无关的——每个模型都变便宜（33-61%）——而质量增益是能力依赖的：模型的增益与其 baseline 强度相关系数近乎完美（r=0.99, n=6），我们称之为 harness leverage。每美元质量提升 82%；每百万 token 的任务完成从 54.9 升至 92.0。在这一工作负载上，编排层对每任务成本的移动超过了整个模型菜单的差异。我们形式化编排层的 token 经济学（包括 prompt caching 下的 effective input price），详述效应背后的六大机制家族——从 cache-shape discipline 到 failure-spend governance——在同一坐标轴上对比 6 大广泛使用的 agent 系统，论证 harness 是唯一一个其效率会跨组织所有模型（现在与未来）复利放大的组件。

核心内容解读（约 550 字）

解决了什么问题：进入 2026 H2，agentic AI 花费失控的隐藏机制被业界普遍误诊为"模型太贵"或"tokens 太长"。本文的企业侧诊断：Claude Code / Cursor / lm-evaluation-harness / Codex 等主流系统都在用 orchestration 层堆 tokens 换能力——longer reasoning traces、更宽的 tool payload、更大的 replayed context、更多轮次。token maxing 掩盖了单价下降，总花费仍在上升。作者提出决定性反问：如果模型不变、单价不变、任务不变，只改 orchestration，成本能降多少？

核心方法：受控置换实验。三大严格设置：(1) 22 个锁定评估任务（企业级 workload：文档、SQL、多步 API、tool payloads 大的场景）· (2) 6 大 foundation model 全覆盖（Claude Sonnet 4.6 · Gemini 3.1 · Gemini Flash 3.5 · Qwen 3.6 · GLM 5.1 · Palmyra X6）· (3) 唯一变量 = harness：冻结生产 loop（"传统"）vs Writer Agent Harness（"实验"）。四指标同时报告：blended cost / task · median wall-clock · tokens / task · task-completion quality。结果：成本 -41%（0.21 → 0.12）· 墙钟 -44%（48s → 27s）· token -38%（14.2k → 8.8k）· 质量 0.78 → 0.81 平齐；每美元质量 +82%，每百万 token 的完成数从 54.9 升至 92.0。

Harness Leverage 现象：每个模型的成本节省是模型无关的（33-61% 全部降），而质量增益是能力依赖的——模型的 harness 增益与其 baseline 强度相关系数 r=0.99, n=6。也就是说：越强的模型越能从更好的 harness 中放大其质量优势——这与"更强模型更省吸 harness 的 leverage"两个方向共同解释了 Claude Opus / Sonnet 4.6+ 时代下 harness 才是差距放大器。

与现有工作的突破点：三条独立立场。（i）区别于 7-08 Yi/Song Harness MDP（学习派）—— 那是 harness 结构本身的学习；本文是 harness 结构整体经济学的工业级测量。（ii）区别于 7-06 ReContext（context 层）· 7-02 Loop Engineering（loop 层）· 6-30 CUGA FLO（策略层）—— 那些是 harness 内部拓扑；本文提供 6 大机制家族的经济学切片：cache-shape discipline / tool-payload governance / turn budgeting / delegation topology / replay compaction / failure-spend governance。（iii）区别于 7-08 The Harness Effect 之前所有综述—— 本文是首个在企业级锁定评估集上一次性测量 6 大主流模型的 harness 差异，并把 prompt caching 下的 effective input price 抬到形式化定义。

H2 harness 谱系再拓展：七层图（7-08 学习派收官）之外，本文开辟第八层：经济学层——把 harness 作为企业组织级组件 而非单模型附属的评估维度。

模型无关性：6 个模型全部变便宜，节省幅度 33-61%——最省的模型是 Gemini Flash 3.5（-61%），最贵不省的模型也降 -33%，无一例外。

Harness Leverage：模型 baseline 强度 vs 质量增益（r = 0.99, n = 6）

作者提出harness leverage：一个模型在换到更好 harness 时的质量增益与其在原 harness 下的baseline 强度 相关系数几近完美（Pearson r = 0.99, n = 6）。这意味着：

  • 成本节省是"分红"——每个企业模型都能拿到（33-61%），几乎与模型能力无关；
  • 质量增益是"杠杆"——越强的 baseline 模型（如 Claude Sonnet 4.6、Palmyra X6）能从更好 harness 中放大 其质量优势；
  • 企业运营含义：如果一个组织在 6 个模型中同时运行 workflow，那么换 harness = 全组织复利收益——这是模型侧升级（一次只升一个模型）不具备的属性。

作者关键论断："在这一工作负载上，编排层对每任务成本的移动超过了整个模型菜单的差异"—— 即 harness 换掉的成本差异，比"从 Claude Sonnet 换到 Palmyra X6"更大。

Harness Effect 背后的六大机制家族
机制家族核心思想典型工程手段
1. Cache-shape discipline让请求形状匹配 provider prompt-cache 命中窗口固定 system prompt / stable prefix / tool schema 前置
2. Tool-payload governance不无脑塞全部工具描述 —— 按上下文 route 工具子集tool subset selector + tool schema minimization
3. Turn budgeting预算式 loop 而非无限迭代 —— 命中预算即 escalate 或 fallbackhard-cap turns + graceful termination
4. Delegation topologyPlanner-Executor / Router-Worker 层次减少无效轮次skill selector + delegation prompts
5. Replay compaction不重放完整轨迹 —— 摘要 + evidence pointertrace compression + evidence store
6. Failure-spend governance失败时不无限重试烧 token —— 熔断 + 反弹策略circuit breaker + failure classifier + downgrade

Effective input price under prompt caching：作者形式化定义 p_eff = α · p_input + (1 − α) · p_cached，其中 α 是 cache-miss rate。cache-shape discipline 通过降低 α 让 p_eff 结构性下降——这是六大机制里最容易量化、也最容易被忽视的经济杠杆。

对研究方向的启发
对 Harness Engineering

H2 harness 谱系再拓展：七层图（7-08 学习派收官） 之外，本文正式开辟 第八层：经济学层——把 harness 从"技术层"抬到"企业组织级经济杠杆"。方法学可复用：(1) orchestration-only 受控置换实验设计——保持模型、任务不变，只换 orchestration，是可直接迁移到 lm-evaluation-harness / HELM / OpenAI evals 的实验协议；(2) 4 指标同时报告（cost / wall / tokens / quality）应成 leaderboard 新标准；(3) 六大机制家族 提供 harness 优化的可分解 checklist——每个家族可单独消融量化；(4) effective input price under prompt caching 应写入 harness 报告标准脚注。

对 Agent Safety

本文六大机制家族里"Failure-spend governance"直接映射 7-08 Doomed from the Start / Recall-Controlled Probe Cascade（agent-safety 早期终止派）——两者独立发现同一个真理：失败时的 token 花费是企业级 agentic AI 最大浪费点之一。7-08 从agent 内部残差流预测失败早期终止，本文从企业外部熔断+反弹策略硬防失败预算爆炸——二者形成"内-外双闸" 组合。Delegation topology 家族与 今日 agent safety 报告（2607.07097 Operational Reframing）形成关联：本文用 planner-executor 拓扑降 token，而今日 safety 报告揭示同拓扑下的 approval-framed delegation 风险——同一拓扑决定成本与安全，需联合优化。

对 Benchmark

"benchmark 数字是 harness 依赖的" —— 本文与 7-06 SafetyRepro（configuration 单变量翻转 pairwise 结论）· 7-08 Yi/Song Harness MDP（+18.2 pp τ-bench） 三方独立证据表明：同一模型换 harness 就能变便宜或变强。leaderboard 必须显式标注 harness 配置——本文的 6 模型 × 22 任务锁定评估集协议可作为 benchmark reproducibility standard v2 参考。此外，token-per-completion 应成新的 leaderboard 一列——本文 54.9 → 92.0 之类数字比 raw score 更有工业信息量。H2 benchmark 方法学第八联：经济学联——把 cost / token-efficiency 抬到 benchmark first-class 变量。
